## 1. 扭曲效果“失效”的根因

### 1.1 参数单位前后不一致

UI 把 `bulge / pinch / twist / wave / displacement` 的参数标成“像素/半径”，
但 shader 里把 `amount` 当成 **UV 比例**，并且 `wave` 的频率用了一个魔法系数：

```glsl
/* 旧代码 */
wave = sin((luv.x + luv.y) * Frequency + Phase) * Amount * 0.001;
offset = n * Amount * 0.001;
```

后果：

- 1920 px 的图层上 24 的强度只有约 7 px，看起来“没反应”；
- 200 px 的标题上只有 0.7 px，完全看不见；
- `wavelength = 180` 经过 `* 0.02` 后实际波长约 314 px，和 UI 标称不一致；
- `pinch` 注册表里根本没有 `radius` 参数，却依赖 shader 的 `Radius`，只能吃 0.5 的兜底值；
- 圆的半径按“图层高度”归一化，宽图层的角落永远在半径外。

### 1.2 修复

`ShaderSources.DISTORT`：

- 半径按**图层半对角线**归一化：`dist = length(ldir * LayerSize) / (length(LayerSize) * 0.5)`，
  `radius = 1.0` 正好到四角，任何宽高比都成立；
- `wave` 用 `travel * Frequency`（像素），`Frequency = 2π / wavelength`；
- `displacement` / `wave` 的像素位移先除以 `LayerSize`，再经 `localDeltaToComp`
  回到合成空间，因此会跟随图层旋转/缩放；
- `bulge/pinch` 的衰减改成 `smoothstep`，并 clamp 到 `0.08..3.0`，
  避免大半径把图层“翻面”。

`EffectRenderer`：

- `Frequency = 2π / max(1, wavelength)`；
- `Radius` 兜底从 `0.5` 改为 `0.75`；
- `Amount` 兜底按像素给（displacement 48、wave 24）。

`CompEffectRegistry`：

- `pinch` 新增 `radius` 参数；
- `bulge/pinch/twist` 默认半径 0.75、默认强度提高；
- 参数名标注“（像素）”。

### 1.3 回归测试

新增 `ShaderDistortTest`：真实 GL 上下文、64×64 源纹理中心 16×16 白块，
运行 `DISTORT` 的 bulge 模式，断言 **方块外侧的 (42,32) 被拉成白色**，
中心仍不透明。测试实际执行（`skipped=0`），不是被跳过的。

## 2. 图形调色（AE / PR 风格）

### 2.1 页面

右侧新增“调色”页（`PAGE_GRADE`）。如果所选图层没有 `color_grade`，显示“添加调色效果”；
添加后是：

- 三个 **色轮**：阴影 Lift / 中间调 Gamma / 高光 Gain；
- **主曲线**：黑 / 阴影 / 中间调 / 高光 / 白 五个控制点；
- 预设：中性 / 电影 / 暖阳 / 冷峻 / 黑白；
- 曝光、对比度、饱和度、自然饱和度、色温、色调；
- 重置 / 移除。

色轮与曲线都是自绘 `UIElement`，但颜色、字体、鼠标行为遵守 BBS 风格；没有引入
HTML/MCEF，也没有改关键帧菱形。

### 2.2 色轮

`UIColorWheel`：

- 中心 = 中性 `0xFF808080`，角度 = 色相，半径 = 饱和度，下方滑条 = 明度；
- 色盘用 AWT 烘一张 128×128 纹理（`GlTexture`），不是每帧画几千个方块；
- 当前明度用 tint 压暗色盘，看到的就是实际会用的颜色；
- 拖动时只写颜色，松手才 `save()`，避免每帧 JSON 落盘；
- 双击复位为中性灰。

### 2.3 曲线

`UICurveEditor`：

- 五个点横向固定、纵向拖动；
- 曲线用与 shader 完全相同的 Catmull-Rom（Hermite 形式）求值，
  所以“看到的曲线 = 渲染的曲线”；
- 双击某点复位；
- 拖动写参数，松手保存。

`ShaderSources.GRADE` 新增：

```glsl
uniform float CurveBlack, CurveShadow, CurveMid, CurveHighlight, CurveWhite;
uniform float Vibrance;
```

曲线是主色调曲线（RGB 三通道同一条），端点可轻微抬升/压暗但不会整体反相。
`CompEffectRegistry` 增加 `vibrance` 与五个 `curve_*` 参数，旧工程缺参数时走默认 0。

### 2.4 为什么不是 LUT

真正的 3D LUT/OCIO 需要新的纹理管线和色彩管理；本轮先用 5 点主曲线 +
三段色轮覆盖 90% 的“给画面调个色”的需求，且参数仍然可以打关键帧、参与效果栈排序。
这是有意的范围控制，不是遗漏。

## 3. 界面逻辑与可拖拽布局

### 3.1 标签栏真正的问题

`UICompTabBar` 原来用 `row(2)` 均分宽度，而 BBS 的 `row()` **无视子元素 `w()`**。
7 个中文标签被塞进 7 个约 42 px 的槽位，文字互相重叠，点击命中区也跟着错位。
上一轮“标签切不了”看似修好了，实际上只是勉强能点。

修复：标签栏改为绝对定位，按文字长度算宽度（`14 + 字数 * 10`），
`效果控件` 54 px、`调色` 34 px……总宽约 270 px，不再重叠。

### 3.2 可拖拽分栏

已有三个 splitter，本轮补齐：

- 左栏、右栏、时间轴高度都可以拖；
- **关键帧抽屉也能拖**（新增第 4 个 splitter，96 px ~ 时间轴高度-96 px）；
- 拖拽时显示 4 px 高亮，松手写入工程 `settings`；
- 关键帧抽屉高度也持久化（`keyframeDrawerHeight`，默认 190）；
- `applyLayout()` 对短窗口做钳制：时间轴最高 = 面板高 - 24 - 160 - 18，
  避免预览与时间轴重叠；
- 关键帧标题宽度让出右侧按钮区，不再压在图标下面。

### 3.3 按钮与提示

能按钮化的入口都改成按钮，并补 tooltip：

- 顶栏：保存 / 播放 / 渲染 / 设置（齿轮）/ 聚焦；
- 时间轴：拆分、标记、吸附、关键帧、缩放、适配、快捷键；
- 关键帧抽屉：上一个 / 添加 / 下一个 / 适配 / 关闭；
- 调色：预设、重置、移除；
- 素材库：导入、插入、替换、刷新、关闭；
- 设置：重置布局、工程列表、快捷键表。

## 4. 素材库与音效库

### 4.1 分类溢出

旧版 9 个分类按钮按 104 px 排成一行，总宽 848 px，而弹窗只有 660 px，
右侧分类根本点不到。现在：

- 13 个分类，7 列 × 2 行；
- 弹窗 700×440，网格 6×4，底栏两行按钮；
- 分类：项目 / 物品 / 方块 / 实体 / 界面 / 粒子 / 状态 / 画 / 环境 / 杂项 / 地图 / BBS / 音效。

### 4.2 素材变多

索引根目录从 7 个扩到 10 个：

```
textures/item, block, entity, gui, particle,
mob_effect, painting, environment, misc, map
```

另加 **BBS 命名空间**（`bbs:textures/...`）。`ImageTextureCache` 原来只认 `mc:`，
现在任意 `namespace:textures/...` 都能从 ResourceManager 读取，BBS 图标可以直接插入图层。

### 4.3 搜索

搜索不再只搜当前分类：

- 输入关键词后同时搜项目素材、全部纹理分类、BBS 纹理、全部音效；
- 匹配名称或路径；
- 网格右下角显示来源分类；
- 清空搜索回到当前分类。

### 4.4 音效库

“音效”分类：

- 索引所有 `SoundEvent`（含 `minecraft:` 与 `bbs:`）；
- 单击试听，双击试听；`替换当前图层` 变成 `复制 ID`，把 `minecraft:xxx` 复制到剪贴板；
- `导入图片…` 在该分类变成 **BBS 音效库…**，直接打开 BBS 原版
  `UISoundOverlayPanel`（和影片编辑器同一个音效选择器），选中的 `Link` 会复制到剪贴板。
- 没有伪造一套音效数据；原版音效列表就是 BBS 自己的列表。

> 限制：合成器目前没有音频轨道，音效库的职责是“试听 + 取 ID + 交给 BBS 音效系统”。
> 让合成器直接往 F6 录像里混音需要新的音频管线，不在本轮范围。

## 5. 开始引导页与项目列表

### 5.1 行为

新增 `UIStartScreen`，覆盖整个合成器面板：

- 左侧：新建工程 / 刷新工程列表 / 快捷键方案 / 返回影片编辑器；
- 右侧：工程列表（名称 + id + 分辨率 + 帧率）、当前工程摘要、进入合成器；
- 双击列表项或回车直接进入；
- 没有选择工程时“进入合成器”禁用；
- 新建工程表单：名称、画布预设、宽高、帧率、时长；
- 工程保存到 `config/bbsae/projects/<id>.json`。

### 5.2 强制先选工程

- 从仪表盘直接打开合成器：`project == null` → 必出引导页；
- 从影片/回放的“打开合成器”进入：自动绑定该影片工程，但仍显示引导页并把该工程标成
  “● 当前”，必须点“进入合成器”才进入编辑；
- 从合成器 clip 的“打开合成器…”进入：clip 已经明确指向工程，直接进入（不再二次询问）；
- 引导页显示期间，编辑器快捷键全部被拦截，只允许输入框与 Esc；
- “返回影片编辑器”在没有影片时不会把用户丢进空编辑器，而是提示先选工程。

### 5.3 工程 id

`CompStore.safe()` 会把中文替换成下划线。新建工程时如果 safe 后只剩 `_`，
改用 `proj_<hash>`，再走 `_2/_3` 去重，避免所有中文工程都变成 `___`。

## 7. 图层时长

旧版只能拖轨道两端，或者看只读的“入/出/时长”文本。现在“片段”区提供：

- 入点（秒）、出点（秒）、时长（秒）三个数值框；
- 1s / 2s / 5s / 整段 四个按钮；
- 入点=播放头 / 出点=播放头；
- 跳到入点、复制、删除。

数值编辑调用 `CompLayer.trimInTo / trimOutTo`，保持素材内容不滑移；
编辑时不再重建整个检查器（否则正在输入的框会被销毁）。

设置里新增 **默认图层初始时长**（秒，0 = 铺满合成）。新图层从播放头开始，
出点 = 入点 + 默认时长；0 时铺到合成结尾。

## 8. 运动模板与方块破碎

### 8.1 运动模板

`CompMotion` 内置 10 个模板：

淡入、淡出、从左/右/上/下滑入、弹入、旋转进入、呼吸缩放、漂浮。

模板在**图层入点**写关键帧（不是合成 0 秒），移动/裁剪片段后仍然对齐；
只写变换/不透明度，不碰内容、效果、蒙版。`CompMotionTest` 4 个测试覆盖。

### 8.2 方块破碎

`block_shatter` 参数扩为：

| 参数 | 含义 |
| --- | --- |
| progress | 进度 |
| blocks | 每边方块数 |
| spread | 飞散距离（格） |
| rotation | 每块旋转量 |
| gravity | 重力 |
| seed | 随机种子 |

shader 改为**逆向映射**：输出像素属于哪个方块，就减掉该方块的位移/旋转，
再采样源图；位移后落在方块外的像素直接透明，因此裂缝是真的缝隙，
不是给原图叠一层网格。方块边缘有内描边，碎片更像“块”。

## 9. 影片编辑器里的合成器 clip

- 默认 `title` 从 `Compositor` 改为 **合成器**；旧 clip 在 `ensureForFilm` 时自动改名；
- clip 检查器改成：
  - 工程 / 合成文本框；
  - “选择工程…”（列出 `.bbscomp`）；
  - “绑定到当前回放工程”；
  - “打开合成器…”；
  - 分辨率/帧率/时长/图层数信息；
  - 适配改为 **适应 / 填充 / 拉伸** 下拉，而不是 0/1/2 数字；
  - 时间：offset / timeScale / opacity；保持末帧。
- `bindComposition` 不再因为“合成 id 不存在”就把整个工程换回影片工程，
  而是在原工程里回退到第一个合成。

## 10. 外部播放回放开关

`CompProject.CompSettings.showDuringExternalPlayback`（默认 true）：

- 设置页提供开关；
- `CompositionOverlay` 用 `BBSRendering.isCustomSize()` 判断是否在影片编辑器/录像器：
  - customSize = true → 编辑器预览或 F6 录像，永远显示；
  - 否则视为外部回放，读取工程设置决定是否叠加。

这样即使录像器在写帧时把 dashboard 隐藏，也不会把导出误判成“外部播放”。

## 11. 导出

### 11.1 自定义比例

导出弹窗（540×400）现在有：

- 常用宽度 1280 / 1920 / 2560 / 3840；
- 比例 16:9 / 9:16 / 1:1 / 4:3 / 21:9 / 2.35:1；
- 自定义宽、高（16..7680 / 16..4320）；
- 自定义比例数值（宽/高，例如 2.35），点“应用比例”按当前宽度重算高度；
- 24 / 30 / 60 / 120 fps；
- 一键 1080p60；
- 仍然走 BBS 原生录像器，不新增导出管线。

### 11.2 真实 1080p60 导出复验

本轮用开发客户端真实导出：

```
ffmpeg -f rawvideo -pix_fmt bgr24 -s 1920x1080 -r 60.0 ...
```

结果：

- 文件：`run/config/bbs/movies/2026-10-18_17-16-53.mp4`
- `ffprobe`：`width=1920 height=1080 r_frame_rate=60/1 nb_frames=494`
- 时长 8.23 s；
- 抽帧 `docs/verify/round6-export-1080p60.png` 中可以看到世界背景上的
  合成器面板、标题 “BBS COMPOSITOR”、副标题和进度条，
  证明不是只导出了世界帧。

日志证据：`Debug export started: 1920x1080 @60fps film=export_test`，
随后 ffmpeg 参数为 `-s 1920x1080 -r 60.0`。
