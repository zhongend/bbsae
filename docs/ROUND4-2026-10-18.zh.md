# 第四轮修复：效果空间 / 摄像机 / BBS 预览（2026-10-18）

> 这一轮修的是**渲染坐标与 BBS 预览管线**，不是 UI 装饰。三条根因都来自同一类错误：
> “合成 FBO 的坐标系”与“合成数据的坐标系”不是同一个。
>
> 配套产物：`bbsae-0.1.0.jar`，300552 字节，
> SHA-256 `2EBCAACAD9165569BEAB4B529E7111E6A682CD5808999A8B9686BB5C12E9E324`。

---

## 1. 根因一：合成 FBO 的 V 轴是反的（渐变不跟随图层的真正原因）

合成器把每一层画进一个**合成分辨率**的 FBO：

- 内容用 `new Matrix4f().ortho(0, w, h, 0, ...)` 绘制（**y 向下**）；
- 所以合成 y=0 落在 FBO 纹理的 **v=1**，合成 y=h 落在 **v=0**；
- 全屏 shader 的 `vUv` 是 GL 约定（v=0 在底），于是
  `compY = (1 - vUv.y) * compHeight`。

原有 `EffectSpace` 直接把 `vUv * compHeight` 当作合成 y，导致：

- `LayerU/LayerV` 算出来的“图层局部 uv”在 Y 方向是镜像的；
- 渐变、分形杂色、棋盘、网格、圆、暗角、径向模糊中心、变形类效果全部锚在**合成空间**，
  而不是图层空间；
- 拖动图层时，X 方向还能跟随，Y 方向反向/不跟随，看起来就是“渐变留在原地，形状变成蒙版”。

**修复**（`client/render/EffectSpace.java`）：

```
compPx = (u * compW, (1 - v) * compH)
u_local = (inv.m00*compW/bw)*u - (inv.m10*compH/bw)*v + (inv.m10*compH + inv.m30 - bx)/bw
v_local = (inv.m01*compW/bh)*u - (inv.m11*compH/bh)*v + (inv.m11*compH + inv.m31 - by)/bh
localToCompUv(u,v) = (px / compW, 1 - py / compH)
```

同一根因还污染了两个 shader（`ShaderSources.java`）：

- `DISTORT.localToCompUv / localDeltaToComp`：bulge/pinch/twist/wave/displacement
  的采样结果上下镜像；已在返回 comp uv 时翻转 V、并在 delta 的 Y 上取负。
- `PIXEL` 的马赛克分支：`floor` 出来的格子坐标再采样前也要翻转 V。

回归测试：`src/test/java/dev/bbsae/client/render/EffectSpaceTest.java`（4 个）：
图层中心 = 局部 (0.5, 0.5)、移动后仍锚定图层中心、Y 方向不镜像、identity 空间满足 V 翻转。

## 2. 根因二：摄像机图层被当成纯色层画出来

`CompRenderer.renderCompToFbo` 只跳过了 `null`，没有跳过 `camera`。摄像机层落到
`LayerContentRenderer.draw` 的 default 分支 → `drawSolid`，于是摄像机位置出现一个
100×100 的纯色方块。此外：

- solo 扫描把摄像机也算进去，solo 一个摄像机会把整条合成隐藏；
- `cameraView` 的手动旋转用了 `+angle`，而 look-at 分支用的是 `-angle`：
  关掉“看向目标”后旋转方向会**反过来**（摄像机的视图应该是摄像机旋转的逆）。

修复（`CompRenderer.java` + `LayerContentRenderer.java`）：

- 渲染循环与 solo 扫描都跳过 `camera`；
- `cameraView` 统一 `rotateZ(-angle)`，look-at 与手动旋转同一套符号；
- `LayerContentRenderer` 增加 `case "camera": break;` 作为第二道保险。

回归测试：`CameraViewTest`（4 个）：中心 identity、pan 反向、手动旋转与 look-at 一致、
顺时针转摄像机时世界逆时针转。

## 3. 根因三：BBS 预览层从来没有拿到过一帧（以及第二次踩坑）

这是用户说“BBS 预览图层根本不生效”的根因。BBS 2.7 的真实管线（源码在
`_research/bbs-fs-1.20.1`）：

1. `BBSRendering.setCustomSize(true, w, h)` 打开后，`onWorldRenderBegin()` 才会
   `toggleFramebuffer(true)`，把世界渲染进 BBS 自己的 framebuffer；
2. `onRenderBeforeScreen()` 把该 framebuffer blit 到 `BBSRendering.getTexture()`；
   `UIFilmPanel.renderPanelBackground` 画的就是这张纹理，录像器读的也是它；
3. 影片编辑器在 `enterEditing()` 里 `setCustomSize(true)`，并把
   `RunnerCameraController` 加进全局摄像机控制器、由 `FilmEditorController` 画回放实体；
   离开编辑器时 `leaveEditing()` 又把这三样全部拆掉。

合成器是**另一个 dashboard panel**，打开时影片面板 `disappear()` → `leaveEditing()`，
于是 customSize 关闭、runner 移除、回放实体不再画。`getTexture()` 里剩下的是
上一次（甚至是空）的帧 —— 预览层于是黑屏/透明。

### 3.1 第一次尝试（错误，必须记住）

第一版 `BbsPreviewBridge` 直接照搬影片编辑器：在合成器 `onAppear` 里
`BBSRendering.setCustomSize(true, compW, compH)`、重挂 runner、重画 actors，
然后让预览层采样 `BBSRendering.getTexture()`。

**结果：合成器页面整个变空白，其他 BBS 页面都正常。**

根因：`setCustomSize` 是**全局模式**。打开后世界渲染进 BBS 的 framebuffer，
`onRenderBeforeScreen`/`toggleFramebuffer(false)` 会把 BBS framebuffer **blit 到屏幕**；
影片编辑器靠 `filmPanelShowing` 分支跳过这次 blit，而合成器不是 `UIFilmPanel`，
所以世界帧覆盖了合成器页面的 UI。其他页面没有开 customSize，所以正常。
实机诊断（把 UI 回读到 PNG）确认：开 customSize 时 FBO 里只有世界；关掉后合成器 UI 完整。

**结论：合成器绝对不要为了拿 BBS 预览纹理去开 `setCustomSize`。**

### 3.2 最终方案：自己抓世界颜色

新增 `client/render/SceneColor.java`：

- 世界照常渲染进 Minecraft 主 framebuffer（customSize 始终为 false）；
- `WorldRenderEvents.LAST` 时 `glCopyTexSubImage2D` 把主 framebuffer 的颜色复制到
  自己的 `GlTexture`（窗口分辨率，GL 底部朝上）；
- `BbsPreviewBridge` 只负责：
  - 把影片面板的 `RunnerCameraController` 重新加进 `BBSModClient.getCameraController()`，
    `setWork(film.camera)`；
  - `WorldRenderEvents.AFTER_ENTITIES` → `FilmEditorController.startRenderFrame/render`
    画回放实体；
  - 每帧 `sync(time)`：`runner.setCursor(time * 20)`（BBS 相机轨道 20 tick/s），
    合成器播放头一动，机位和回放就走；
  - `onDisappear` / 关闭面板时移除 runner。
- 预览层与预览背景都采样 `SceneColor.texture()`，**完全不碰 `BBSRendering` 的任何状态**。

另外两个让“预览层看起来没生效”的问题也一起修了：

- `addLayer("bbs")` 原来 `doc.addLayer(layer)` **追加到最上层**，会把整条合成盖住；
  现在插到 `layers.add(0, ...)`（最底层），并且同一合成只允许一个 BBS 预览层；
- 预览背景新增开关：预览左上角 **BBS** 按钮 / `CompSettings.previewBackground`
  （0=编辑底色，1=实时世界画面），按 cover 缩放画在合成矩形内。

**作用域**：`BBS 预览` 图层只在合成器面板可见（`BbsPreviewBridge.isActive()`）时参与渲染。
在 BBS 影片 overlay / F6 导出链路里，世界本来就在合成下面，而且抓取纹理是上一帧
（会形成反馈），所以这条路径下该层**直接跳过**，不画占位、不画黑块。

**回放实体的 context 修复**：影片面板隐藏后会被移出 dashboard 元素树，
`UIFilmController.getContext()` 随之变成 null，`isPlaying()` 里 `UIOverlay.has(null)` 会 NPE，
表现为预览里**只有世界没有回放**。`BbsPreviewBridge` 现在会把 controller 临时挂到一个
不可见的 carrier（`dashboard.main` 下），让它能沿父链拿到根 context；`detach()` 时再放回影片面板。

**实机证据**（ASCII 路径副本 `C:bsae-dev2`，`-Dbbsae.debugPreview=true`）：

```
[BBS film] custom=false
(bbsae) BBS preview layer composited a 1920x1080 world frame
```

UI 回读截图 [`docs/verify/compositor-world-gradient-2026-10-18.png`](verify/compositor-world-gradient-2026-10-18.png)
同时显示了完整合成器界面、世界帧背景与渐变形状。

## 4. 新功能：形状填充渐变（参考 EffectCraft）

`CompShape` 新增：

```java
boolean fillGradient;
int fillColor2;
float fillGradientAngle;
```

`ShapeCache` 用 AWT `GradientPaint` 在**形状局部空间**按包围盒画两段渐变，再栅格化。
渐变是形状纹理的一部分，所以移动/缩放/旋转/父级/蒙版/效果都天然跟随，不存在
“渐变和形状分离”的可能。`hash()` 已包含这三个字段，改颜色/角度会正确失效缓存；
`fillGradientAngle` 支持关键帧（`shape/<id>/fillGradientAngle`）。
检查器「形状」页新增：填充渐变开关、渐变颜色 2、渐变角度。

## 4.5 界面逻辑修复：预览点击/拖动

旧逻辑：只要预览区域里按下左键，就拖动**当前选中**的图层，哪怕点在空白处；
点击也不能改选其它图层。现在：

- `preview.layerAt(context)` 从最上层往下做命中测试：形状用 `ShapeCache` 的光栅包围盒，
  其它图层用锚点包围盒；鼠标先换算到合成坐标，再用 `worldMatrix` 的逆矩阵变换到图层局部
  （父级和摄像机都包含在内）；
- 点中图层 → `selectLayer` 并开始拖动；点中锁定图层 → 只选中并提示，不拖动；
- 点空白 → `clearSelection()`，右侧进入真正的空状态；
- 预览的其它交互（标尺、轨道）不受影响。

**不要用 `Compress-Archive` 生成 jar。** Windows PowerShell 5.1 的 `Compress-Archive`
会把条目名写成 `dev\bbsae\...`（反斜杠），Fabric 找不到类。之前记录里“先 zip 再改名”
只在某些 PowerShell/.NET 版本安全。这一轮改用 JDK 自带 `jar`，可正常写 zip：

```text
$root\_tools\jdk21\jdk21.0.12_12\bin\jar.exe --create
  --file $root\build\libs\bbsae-0.1.0.jar
  -C $root\build\package-r4 .
```

暂存目录 `build/package-r4` = `build/remap-final11/*` + `build/resources/main/*`
（+ 可选 `META-INF/MANIFEST.MF`）。

## 8. 下一轮优先项

1. **视觉回归**：真实客户端里给“形状 + 渐变”拖动前后各截一张图；再截 BBS 预览层、
   BBS 背景开关、摄像机旋转前后。桌面会话切不到前台时，用 `-Dbbsae.debugPreview=true`
   启动后看日志 + 让用户手动截图。
2. **BBS 预览与影片同步**：目前 `sync()` 在 UI 渲染时调用，比世界渲染晚一帧；
   如果要逐帧严格同步，把 `sync` 挪到 `WorldRenderEvents.BEFORE_ENTITIES`。
3. **BBS 预览的构图**：现在按 comp 尺寸拉伸世界帧（与 BBS 影片面板一致）；
   如果窗口不是 16:9，需要 letterbox 而不是拉伸。
4. **摄像机**：目前仍是 2D 双节点摄像机（位置/目标/缩放/旋转），没有 Z/景深/3D 图层；
   `cameraZ/cameraTargetZ` 字段还没参与运算。若要 3D，按 `BindingResolver` 的投影思路扩展。
5. **形状渐变**：目前多形状图层共用一次填充（最后一个渐变形状决定），
   单形状图层完全正确；多形状需要按 shape 分别生成 paint 或分层。
