## 1. 第一性原理：界面"臃肿"到底是什么

界面的信息密度只有一个度量：**一屏能放下多少个可操作单元**。

```
行密度 = 可用高度 / (控件高度 + 行间距)
信息量 = 可见行数 × 每行信息
```

旧界面把三件事固定死了：

1. **控件高度写死 18/20/22px**，而 BBS 自己的控件是 `UIConstants.CONTROL_HEIGHT = 16`；
2. **标签列写死 90px**，短标签（"X"、"宽"）浪费一半；
3. **每个按钮都用主色填充**（BBS `UIButton` 默认 `BBSSettings.primaryColor`），40 个按钮 = 40 个大色块。

所以"臃肿"不是字号问题，是**三个常量没有随环境变化**：BBS 的界面缩放（GUI scale 1–4）、面板宽度、以及"这个按钮是不是主操作"。

### 1.1 三档密度，自动跟随 BBS

`CompUi` 把上面三个常量收进一张表：

| 档位 | 控件 | 行高 | 间距 | 标签列 | 图标 | 左栏 | 右栏 | 时间轴 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 小（紧凑） | 14 | 16 | 2 | 62 | 16 | 152 | 268 | 232 |
| 中（默认） | 16 | 18 | 3 | 76 | 18 | 178 | 306 | 252 |
| 大（舒适） | 20 | 22 | 4 | 92 | 22 | 208 | 348 | 288 |

**自动档**读 BBS 实际生效的 GUI scale（`BBSModClient.getGUIScale()`，它已经包含 BBS 自己的 `ui_scale` 设置）：

```
scale < 2.01  → 大
scale < 3.01  → 中
否则          → 小
```

直觉上会反过来——"缩放越大字越大，应该用大档"。但 GUI scale 是**窗口像素 / 界面像素**：scale 4 时逻辑画布只有 480×270，行高 22 的面板根本放不下几行；scale 1 时逻辑画布 1920×1080，用大档才不至于让控件显得针尖大。这就是"小档塞下更多信息"的数学来源，也是自动档的依据。

设置位置：**设置 → 界面密度**（跟随 BBS / 小 / 中 / 大），随工程保存（`CompSettings.uiDensity`）。切换后会立即重排左右栏、时间轴，并重建检查器（行高在构造时确定）。

## 2. 按钮：把"色块"还原成"文字 + 灰底 + 图标"

### 2.1 语义

AE 的界面里，**填充色是有含义的**：整个界面通常只有一处实心强调（工具状态、主按钮），其余都是灰色底 + 文字。旧界面把 40 个按钮都涂成主色，等于把强调语义用光了。

`UICompButton` 定义四种语义：

| 样式 | 用途 | 画法 |
| --- | --- | --- |
| `FLAT` | 默认，所有普通操作 | `raisedSurface` 底 + `dividerColor` 1px 边 + 左对齐文字；hover 变 `baseSurface` + 主色细边 |
| `PRIMARY` | 每个面板**只有一处**（播放、进入合成器、应用效果） | 主色底 + 左侧 2px 高光条 |
| `DANGER` | 破坏性操作（暂未大面积使用） | 暗红底 + 浅红字，不用交通灯式亮红 |
| `GHOST` | 工具栏里的无底图标/文字 | 无底无边，hover 才出现浅色块 |

实现上只覆盖 `UIButton.renderSkin()`，点击、hover、右键菜单、禁用态全部沿用 BBS 的 `UIClickable`——没有第二套交互代码。

### 2.2 图标化

凡是"一个符号就够"的动作都换成 16–22px 图标按钮（`UICompIconButton`，hover 才出现底板）：

- 顶栏：新建图层（+）、上一帧/下一帧、聚焦预览
- 时间轴头：缩放 −／+、适配全长、返回上层合成
- 形状标题行：删除（×）
- 预设卡片：删除（×）

`UIIcon` 自带 tooltip，图标按钮的 tooltip 是**必填参数**。

### 2.3 每个按钮都有悬浮说明

`CompUi.describe(label)` 是一本**词汇表**：面板里出现的每个按钮文案都有一条中文说明（70+ 条），例如

```
"合成预渲染" → "把所选图层合并进一个子合成，再用一个预合成图层替换它们；入点会整体前移"
"重置摄像机" → "位置回到合成中心、距离回到 1:1、目标对准中心、滚转归零"
"存为效果"   → "把当前图层整条效果栈存成预设，可套到别的图层"
```

`UICompButton` 构造函数**自动**按标签查表设置 tooltip，所以即使某处忘了写 `.hint(...)`，按钮也一定有说明；显式 `.hint()` 可以覆盖成更具体的句子。查不到的动态标签会退化成 `点击执行：<标签>`，并在前缀匹配（"应用 电影青橙" → "应用" 的说明 + 预设名）后再兜底。

`UICompTest.everyKnownLabelHasADetailedTooltip` 把常用标签的覆盖写成了断言：说明长度 < 8 或落到兜底文案就失败，防止以后新增按钮忘了写。

## 3. 布局重排（不动功能）

- **顶栏**：标题 / 回放选择 / 播放（唯一主色）/ 上一帧 / 下一帧 / 时间码 ｜ 右侧 保存 / 导出 / 渲染 / 设置 / 聚焦，全部扁平，高度随密度。
- **时间轴头**：新建、切分、标记三个图标；吸附、关键帧两个扁平文字按钮；缩放与适配改为图标；`时间轴 / 曲线` 标签条高度对齐。
- **检查器**：所有 `smallButton` 走 `CompUi.flat`（40+ 个）；标签列从 90 → 76（小档 62）；行高从 20 → 18（小档 16）；关键帧小按钮尺寸随控件高度。
- **曲线编辑器工具条**：8 个缓动预设 + 值/速度图表 + 适配/吸附/加键/删键全部扁平，高度 = 控件高度，不再比 BBS 的控件高一头。
- **预设浏览器**：卡片标题变扁平按钮（右侧带删除图标），描述行在下方，卡片高度随密度。
- **设置弹窗**：按钮扁平化；新增"界面密度"一行；"重置面板布局"按当前密度取默认值。
- **引导页 / 效果库 / 合成 clip 面板**：主操作保留唯一主色，其余扁平。

**功能、字段、行为一律未改**：所有按钮仍调用原来的方法，只是换了皮肤和尺寸。

## 6. 进游戏验收清单

1. 设置 → 界面密度：切到 **小**，整块检查器立即变矮、标签列变窄，一屏多出约 4–6 行；切到 **大** 行高明显变大；**跟随 BBS** 时在视频设置里改 GUI 缩放，重开合成器应自动换档。
2. 检查器里随便悬停 10 个按钮：每个都有中文说明（不是"点击执行：X"）。
3. 顶栏：只有"播放"是实心主色，其余是灰底文字；鼠标移上去有边框高亮。
4. 时间轴头：`-`/`+`/适配 是图标；`吸附`/`关键帧` 是灰底文字，不再是大色块。
5. 曲线编辑器工具条：8 个缓动按钮高度与 BBS 输入框一致，不再顶到工具条边缘。
6. 小档 + GUI scale 3 时，左栏三个标签不重叠、右栏属性名不截断（这是紧凑档的下限，若截断请报告具体分辨率）。

## 7. 已知限制 / 下一轮

- 密度切换只重建检查器与分栏；顶栏按钮的尺寸在创建时确定，切换密度后要重开面板才会完全一致（不影响可用性）。
- `UISection` 的标题条高度是 BBS 的固定值（`HEADER_HEIGHT`），没有随密度缩放——它是 BBS 原生控件，改它会影响别的 addon。
- 图标按钮目前只用了 BBS 自带图标；以后可以引入一套线性图标（AE 风格）替换 `+`/`-`/适配等。
- 提示词表是中文硬编码，等 BBS 的 i18n 键稳定后再迁移。
