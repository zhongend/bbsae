# bbsae 交互逻辑审计

**审计对象**：bbsae 0.1.0（27,825 行 Java；主面板 `UICompositorPanel` 8,375 行；轨道时间轴 `UICompTrackTimeline` 1,466 行）
**审计日期**：2026-10-24
**范围**：只找“程序没坏，但用户的意图和界面给的路径对不上”的逻辑问题；不包含崩溃、GL、性能。
**参照系**：Premiere Pro 的操作模型；以及项目自己的 `docs/compositor-plan-v2-1.20.1-full.zh.md` §7（这份计划本来已经写明了图层栈、效果列表、蒙版钢笔、预览缩放、撤销按钮等交互，现状有相当一部分没有落地）。

**方法与证据**：通读 `UICompositorPanel`（构造函数、绑定/生命周期、检查器构建、时间轴、关键帧、素材库、导出、引导页）、`UICompTrackTimeline`、`UIEffectLibrary`、`UICompositorKeyframes`、`UIAssetBrowser`、`UIStartScreen`、`CompDocument/CompLayer/CompStore`、`CompExportManager`、`LayerContentRenderer`；并用 `javap` 对照 `libs/bbs-2.7-1.20.1.jar` 的 `UISection`、`UITimelinePanel`、`UIKeyframeEditor`、`UIList/UIItems` 行为，确认“折叠后 controls 消失”“关键帧属性面板挂在 target 上”“列表回调是选中项”等结论。所有“证据”行都给到文件与行号。

## 0. 结论先说

你发现的两个问题不是孤立的。它们是同一条根因的两个症状：

> **“选择”和“编辑”不在同一个地方；“容器”在界面上没有形状。**

当前实现把图层、关键帧、合成都压成了“一条横条 + 右侧一个长表单”。所有结构信息——谁在谁里面、谁影响谁、哪个关键帧被选中、效果栈是什么顺序——都被藏进了颜色、图标或另一个 tab。

本次共记录：

- **8 个 P0**：会改错结果、丢工作，或者让用户以为操作成功但其实没有。
- **14 个 P1**：主工作流被切断，用户必须跨面板、跨屏幕、靠记忆完成。
- **27 个 P2**：结构、状态、一致性、响应式布局问题。

最危险的不是“多点两下”，而是三处**静默改错**：

1. 预合成把内容放到了错误的时间（从 5 秒开始的图层预合成后可能完全消失）。
2. 选中关键帧后改值，值写到了播放头，而不是选中的关键帧。
3. 六种错误提示写进了一个每帧都会被覆盖的 label，所以永远不会出现。

### 直接回答你点名的五条链

> 下表是**审计时**的状态；P0 已在本轮修复，逐项状态见 §8。

| 你的问题 | 直接答案 | 详见 |
| --- | --- | --- |
| 给这层加个效果要几步？ | 典型 **5–8 步**，跨轨道 / 左栏 / 右栏 **3 个区域**；加完新效果还在长列表最底部，第一眼不一定看得到参数 | §2.1、P1-7/8/9 |
| 改一个关键帧的值要跨几个面板？ | **3–4 个区域**：轨道刻度（点了没用）→ 底部抽屉（选中）→ 右栏（值，或被关键帧属性整个覆盖）。而且右栏按播放头写，容易写错帧 | §2.2、P0-2、P1-4/5/6 |
| 进预合成改完再退出来路径有多长？ | 进入有 **2–3 条**路径；退出只有工具条上一个 **20px 返回箭头**（Esc 无效）；进入/退出各丢一次时间和缩放 | §2.3、P1-1/2/3 |
| 效果栈调顺序是不是只能删了重加？ | **不用删**；有上移/下移，但只有 16px、折叠后消失、不能拖、没有复制/粘贴 | §2.4、P1-7/9 |
| 误操作能不能撤回？ | **能，但不可预测**：撤销是 1 秒快照，可能一次退多步；没有 Undo/Redo 按钮；六种错误提示永远不会显示 | §2.5、P0-4、P0-8 |

### 对你已发现的两个问题的定性

- **预合成**：不是“按钮藏得深”这么简单，而是三件事叠加——**容器没有形状**（轨道上不像容器）、**进出不对称**（进入 3 条路、退出 1 个 20px 图标）、**进入不映射时间**（在 8 秒处进去，里面是 0 秒）。只加一个“进入”按钮不会解决后两条。
- **关键帧**：不是“面板位置不好”，而是**一个关键帧有四个编辑面**（轨道刻度 / 底部 dope sheet / 右栏关键帧属性 / 效果控件数值），而且它们对“当前是哪一帧”的理解不一致。只把抽屉挪到右边，仍然会改错帧。

## 1. 我读到的结构

### 1.1 面板清单

| 区域 | 实际内容 | 关键代码 |
| --- | --- | --- |

| 左栏 tab 1 | 效果库：搜索、分类树、最近使用、目标状态、应用按钮 | `UIEffectLibrary` |

| 中央 | 预览 FBO、FX/Mask/BBS 开关、摄像机视图、3D 空间、信息行 | `UICompositorPanel` 351–1697 |
| 右栏 7 个 tab | 效果控件 / 调色 / 图层 / 蒙版 / 文字 / 合成 / 输出 | `UICompositorPanel` 1699–1721 |

### 1.2 数据流

```
CompStore (.bbscomp JSON)
  └─ CompProject
       ├─ comps: List<CompDocument>        ← 多合成，但界面上没有合成列表
       └─ CompDocument
            ├─ layers: List<CompLayer>     ← 顺序：0 = 最底层
            ├─ markers / parameters
            └─ CompLayer
                 ├─ transformChannel / opacityChannel / scalar channels
                 ├─ effects / styles / masks / shapes / textAnimators
                 └─ precompId → 另一个 CompDocument

UICompositorPanel 持有：project / doc / selectedLayer / time
  ├─ CompRenderer.render(...)              → 预览 FBO
  ├─ refreshInspector()                    → 重建右栏（selection / page / 结构变化时）
  ├─ refreshSheets()                       → 重建底部关键帧抽屉的 channels
  ├─ save()                                → 整个工程 JSON 落盘
  └─ captureSnapshot()                     → render() 每帧调用，1 秒节流，最多 50 步
```

关键事实：

- **选择源只有一个**：`selectedLayer`。它由轨道头/轨道 lane、预览命中测试、添加/复制/删除后的赋值来改变。
- **时间源只有一个**：`time`。它由标尺拖动、方向键、播放、关键帧导航来改变。
- **右栏是“重建式”的**：`refreshInspector()` 先 `removeAll()` 再按当前 `inspectorPage` 重建；不是数据绑定。
- **关键帧抽屉是“重建式”的**：`refreshSheets()` 先 `removeAllSheets()` 再按 `selectedLayer.animatedPaths()` 重建。
- **撤销是快照式**：不是命令栈，粒度由 1 秒定时器决定，不是由用户动作决定。

### 1.3 一条操作要经过哪些代码

| 用户操作 | 入口 | 改什么 | 谁刷新 | 用户实际看到 |
| --- | --- | --- | --- | --- |
| 选轨道 | 轨道头 / lane / 预览 | `selectedLayer` | `refreshInspector()` + `refreshSheets()` | 右栏内容整体换掉；底部抽屉换 channels |
| 加效果 | 左栏双击 / 应用按钮 | `layer.effects.add()` | 切到“效果控件”页 + 重建 | 窗口底部状态栏闪一句；右栏可能看不出变化 |
| 打关键帧 | 属性旁秒表 | channel.insert() | `refreshSheets()` + `openKeyframes()` | 底部抽屉弹出，轨道区变矮 |
| 改值 | 右栏数值 / 预览拖动 | 若 channel 有键 → 写播放头；否则写静态值 | 无（值绑定在 time 变化时才回读） | 画面变；但改的是不是你以为的那一帧，取决于播放头 |
| 进预合成 | 双击 bar / 右键 / 图层页按钮 | `doc` 换成 sub，压栈 | `refreshLayers/Inspector/Sheets` | 时间归零、缩放重置、标题不变 |
| 撤销 | Ctrl+Z | 恢复 1 秒前的整工程 JSON | 全部重建 | 可能回退多步；没有按钮、没有动作名 |

## 2. 五条操作链实测

> 以 1920×1080、GUI scale 2（逻辑 960×540）为例。此时 `body` 高度约 220–250px，右栏大约只能看到 10–12 行。

### 2.1 给这一层加个效果

**实际路径**

1. 在轨道上点一下选中图层。
2. 鼠标移到左栏；如果分类是折叠的，先展开或搜索。
3. 双击效果（或选中后点底部“应用效果”）。
4. 鼠标移到右栏；右栏会切到“效果控件”，但滚动位置不变。
5. 向下滚过“片段”（约 8 行）、“运动”（约 9 行）、“运动模板”（4 行按钮），才到“效果”。
6. 新效果在效果栈最底部；继续向下滚，才能看到它的参数。

**断点**

- 第 4 步没有“新效果在这里”的滚动或高亮；“已添加效果”的提示在窗口最底部的状态栏，离右栏更远，用户很容易以为没加上。
- 第 5 步的“片段”和“运动模板”把真正的效果区推到了折叠线以下；在 220–250px 高的右栏里，加完效果第一眼通常看不到参数。
- 不能把效果从效果库拖到某条轨道；只能“先选轨道，再双击”。目标只在左栏底部一行小字里。
- 没有多选图层，不能一次给 5 层加同一个效果；也没有复制/粘贴效果。

**Premiere 对照**：选中 clip → 在 Effect Controls 里双击效果，或把效果拖到 clip 上；Effect Controls 顶部是紧凑的效果栈，新效果立即可见；效果行可拖拽排序。

### 2.2 想改一个关键帧的值

**实际路径（用户以为的）**

1. 在轨道 bar 底部看到一排小白点（关键帧刻度）。
2. 点其中一个 → **什么也没选中**；如果按住拖动，整段 clip 被拖走。
3. 于是去点工具条的“关键帧”按钮 → 底部抽屉弹出，轨道区从 4 条变成 2 条。
4. 在 dope sheet 里找到那个属性、点中那个关键帧 → **右栏整个“效果控件”被一个通用属性面板覆盖**。
5. 在右栏改值。

**实际路径（另一条，用户更容易走的）**

1. 选中轨道，右栏直接改“位置 X”。
2. 因为播放头不在那个关键帧上，`setTransformComponent` 在**播放头**插入了一个新关键帧。
3. 3 秒那个关键帧没变；7 秒多了一个新关键帧。用户以为改的是 3 秒那个。

**断点**

- 轨道上的关键帧刻度是**装饰**：`renderKeyframeTicks` 画了 2×2px 的白点，但 `clickLane` 完全没有命中测试。
- 选中关键帧不会移动播放头；而右栏的值编辑器是按播放头写的。两个时间模型不一致。
- 关键帧属性面板挂在 `target = inspector` 上，会**覆盖整个右栏**；没有标题说明“你现在在编辑 3 秒的关键帧”，也没有返回按钮。
- 抽屉在轨道下方；打开时把轨道区压缩到 70px 左右（2–3 条轨），正在看的那条可能被挤出去。
- 插值/缓动只能在抽屉里右键；轨道上的关键帧没有右键菜单；没有 Easy Ease。

**Premiere 对照**：点轨道上的关键帧菱形 → CTI 移到该帧 → Effect Controls 的数值框编辑的就是这个关键帧；右键就是插值/缓动；不需要离开时间轴。

### 2.3 进预合成改完再退出来

**实际路径**

1. 在轨道上找到“预合成 3”。它看起来和普通片段一样，只是颜色偏橙、图标不同；没有展开箭头、没有缩略图、没有“里面有 5 层”。
2. 双击 bar 进入（双击轨道头是重命名；右键菜单里也有“进入预合成”；右栏“图层”页最下面还有一个按钮）。
3. 进去后：时间归零、时间轴缩放重置、标题不变、顶部仍写“回放：xxx”；没有面包屑。
4. 改完想出来：只有时间轴工具条上一个 20px 的返回箭头（x=258）；按 Esc 没反应。
5. 退出来：父时间恢复，但缩放又重置；再进去又是 0 秒。

**断点**

- 进入路径有 3 条，退出路径只有 1 条，而且退出按钮在工具条中间，不在你点击的容器上。
- 没有“主合成 / 预合成 3”的面包屑；深度 > 1 时更不知道自己在哪。
- 进入不映射父播放头：在 8 秒处进去，里面是 0 秒；你看到的不是外面那一帧。
- 每个合成没有独立的播放头/缩放；切换回放/工程也会归零。
- 没有合成浏览器：不能列出、切换、新建、重命名、删除合成；预合成只能增不能删，名字全是“预合成 N”。

**Premiere 对照**：嵌套序列在时间轴上有序列图标；双击进入后顶部有序列标签/面包屑；每个序列有自己的播放头；返回是点父序列标签；Esc 不是唯一出路。

### 2.4 效果栈想调个顺序

**实际路径**

1. 选中图层，右栏切到“效果控件”。
2. 滚到效果区；每个效果是一整段展开的参数。
3. 在效果标题右侧找启用开关 + 三个 16px 图标（上移 / 下移 / 删除）。
4. 点“上移”一次，`refreshInspector()` 重建整个右栏；滚动位置可能变化，效果的序号也重排。
5. 想把最后一个挪到最前面：点 4 次，且每次都要重新找它在哪。

**断点**

- 效果栈不是“栈”：它是若干整段展开的 `UISection`；顺序不能一眼看清。
- 折叠一个效果想总览顺序时，**启用/上移/下移/删除也一起消失了**，因为它们放在 `fields` 里，不在标题行。
- 不能拖拽；不能复制/粘贴；没有多选图层批量应用；没有“重置效果参数”。
- 删除是 16px 垃圾桶，没有确认；撤销粒度 1 秒。

**Premiere 对照**：Effect Controls 顶部是紧凑的效果名列表；拖拽排序；每行都有开关和删除；参数在选中行下面展开。

### 2.5 误操作能不能撤回

**实际路径**

1. 按 Delete 删掉一个图层（没有确认）。
2. 按 Ctrl+Z。
3. 撤销恢复的是“最多 1 秒前”的整工程快照；如果删除和上一次编辑在同一秒内，**两个一起被撤销**；如果删除后超过 1 秒才撤销，可能只撤销删除。结果取决于你按得多快。
4. 界面上没有撤销/重做按钮，也没有“已撤销：删除图层”的动作名。

**断点**

- 撤销粒度不是“一个用户动作”，而是“一个定时器周期”；用户无法预测一次撤销会退多远。
- 没有可见的撤销入口；不看快捷键表就不知道。
- 删除图层/效果/样式/预设都没有确认。
- 六种失败提示（没打开影片、没选图片层、导入失败、撤销到底等）写进了 `status.label`，但 `render()` 每帧覆盖它，所以**永远不会显示**。

**Premiere 对照**：Ctrl+Z 精确回退一个动作；Edit 菜单/历史面板显示动作名；删除可以在历史里恢复。

## 3. 判断标准：交互第一性原理

把“用户在编辑”拆成最小回路：

> **看见对象 → 选中它 → 看见它的状态 → 改它 → 看见结果 → 不对就撤回。**

任何让这个回路变长的东西都是交互 bug。由此得到 7 条判据：

| # | 原则 | 含义 | 违反后的典型症状 |
| --- | --- | --- | --- |
| 原则 1 | **同一对象、同一时间、同一编辑面** | 选中关键帧后，所有值编辑器必须编辑这个关键帧；不能一套按选中、一套按播放头 | 改 3 秒的键，7 秒多了一个键 |
| 原则 2 | **点击处即编辑处** | 编辑控件出现在点击位置，或在一个固定相邻、不会跑掉的检查器里 | 点轨道上的关键帧，编辑面板在页面另一端 |
| 原则 3 | **容器可见、可进出、可命名** | 容器要有形状、子内容、深度、进入/退出、名字 | 预合成看起来像普通片段，进去出不来 |
| 原则 4 | **一个动作 = 一个可逆步** | 撤销粒度等于用户动作，不是定时器；破坏性操作可确认/可撤销 | 删一个层，撤销退回三步 |
| 原则 5 | **反馈在动作处，失败可见** | 成功/失败出现在操作旁边；不能写进一个会被覆盖的 label | 替换素材失败，界面毫无反应 |
| 原则 6 | **入口承诺 = 出口默认** | 按钮写什么就做什么；入口说“替换”，出口不能“插入” | “替换素材”实际插入新层 |
| 原则 7 | **单一真相** | 一个设置只有一个编辑器；一个对象只有一个顺序模型 | 同一个设置两个地方各一份 |

后面的“根源”都归到这 7 条之一。

## 4. 问题清单

### 4.1 P0：会改错结果或丢工作

#### P0-1 预合成会让内容消失，还会跳到最顶层

**现象**
我把一个从 5 秒开始、到 8 秒结束的图层做“预合成”。结果 5–8 秒之间画面完全空了；预合成后的层还跑到了最顶层，把上面的文字盖住了。如果这个层原来有父级或轨道遮罩，关系也一起没了。

**为什么难受**
在 Premiere 里，Nest 之后 clip 还在原来的时间位置、原来的轨道层级；嵌套序列里的内容和外面看到的一致。这里 Nest 同时改了三件事：时间原点、层序、父子/遮罩关系，而界面没有任何提示。

**根源**
容器操作没有保持两个不变量：**时间原点**和**层序**。属于原则 1（同一时间模型）+ 原则 3（容器）问题。

**证据**
`UICompositorPanel.precomposeSelected` 5078–5096：`copy = source.duplicate()` 保留了 `copy.in/out`；新 precomp 层 `in = source.in`、`startTime = 0`；`doc.addLayer(precomp)` 追加到列表末尾（视觉最顶层）。`LayerContentRenderer.drawPrecomp` 286–293 用 `(compTime - in + startTime) * scale` 作为子合成时间，所以父时间 5 秒对应子时间 0 秒，而子层 `in=5`，`activeAt(0)` 为 false；要等父时间 10 秒才可见，但 precomp 层 8 秒就结束了。

**第一性修复**
预合成时：

1. 把新 precomp 层插到**源图层的原索引**，不要 `addLayer` 追加。
2. 子合成内把 copy 的 `in/out` 归一到 0 / (out-in)，并把所有关键帧和标记整体平移 `-in`；`copy.startTime` 保留原值（它承载素材自身的裁剪偏移）。
3. 把源图层的 `parentId / trackMatteId / trackMatteMode` **转移到新 precomp 层**（父级/遮罩层通常留在外层），子合成内的 copy 清空；不要静默丢失。如果父级/遮罩也被一起带进子合成，才在内部重建关系，并提示用户。
4. 加回归测试：`in=5, out=8` 的图层预合成后，父时间 5/6/7 秒可见，画面源时间与预合成前一致；层序不变。

#### P0-2 选中关键帧后改值，值写到了播放头

**现象**
我在底部关键帧面板里点中 3 秒的一个位置关键帧；播放头还停在 7 秒。我以为“选中了 3 秒的键”，于是去预览里把图层拖到新位置——结果 3 秒的键没变，7 秒多了一个新键。换一个入口（Alt+K、预览拖动）结果都一样：只要不是在那个点关键帧才出现的通用属性面板里改，写的就是播放头。

**为什么难受**
在 Premiere 里，点关键帧 → CTI 跳到该帧 → 所有值编辑器（Effect Controls、Program Monitor、快捷键）编辑的都是这个关键帧。这里“选中的关键帧”和“值编辑器认的时间”是两个不同的东西，界面没有任何提示；用户从最自然的入口（预览拖动/右栏数值）改，就会写错帧。

**根源**
两套时间模型并存：BBS dope sheet 的“选中关键帧”模型，和 bbsae 右栏的“播放头”模型。属于原则 1。

**证据**
`UICompositorPanel.setTransformComponent` 7300–7335 用 `this.getFrame()` 插入；`UICompositorKeyframes` 没有覆盖 `pickKeyframe`；BBS `UIKeyframes.pickOrStartSelectingKeyframes` 只 `selection.add(found)`，不移动 `getTick()`。

**第一性修复**
在 `UICompositorKeyframes` 覆盖 `pickKeyframe(Keyframe)`：调用 super 后 `panel.setFrame(keyframe.getTick())`。这样“选中关键帧 = 播放头 = 值编辑器目标”三者一致。再加一个测试：播放头在 7 秒、选中 3 秒关键帧、改值，断言只有 3 秒的键变化。若不想移动播放头，就必须让右栏数值框在“有关键帧被选中”时写选中键，并显示“关键帧 @ 3s”；两者选一，不能并存。

#### P0-3 同一个“入点”，时间轴和图层页两种结果

**现象**
我在时间轴上把片段左边缘往右拖，画面内容保持连续；我在右侧“图层”页把“入点”改成同样的数值，画面内容跳了（尤其是图片序列、带时间重映射或已经裁剪过的素材）。同一个入点，两个地方两种结果。

**为什么难受**
在 Premiere 里，入点就是入点，无论在时间轴拖还是在 Effect Controls 里改，素材的源时间都连续。这里“图层页”直接写 `layer.in`，没有补偿 `startTime`，所以素材源时间被整体平移了。

**根源**
同一属性有两个写入口，其中一个绕过了时间语义。属于原则 7（单一真相）。

**证据**
`fragmentSection` 5274–5290 用 `trimInTo`（内部 `startTime += delta`，`CompLayer` 767–778）；`layerSection` 6199–6200 直接 `l.in = value` / `l.out = value`。后者还不校验 `out >= in`，也不 `save()`。

**第一性修复**
删掉 `layerSection` 里的原始赋值，全部走 `trimInTo/trimOutTo`；如果确实需要“改源时间偏移”，单独做一个“源时间偏移”字段，并明确标注它不是入点。加测试：从两条路径把入点从 0 改到 5，断言 `startTime` 和 `sourceTimeAt` 一致。

#### P0-4 六种错误提示永远不会出现

**现象**
没打开影片点“导出”、没选图片层点“替换”、撤销到底、导入失败——底部状态栏不会出现这些话，界面像是什么都没发生。

**为什么难受**
在 Premiere 里，失败会弹对话框或在面板内显示红色提示。这里失败是静默的，用户只能反复点、猜。

**根源**
反馈写进了一个每帧都会被覆盖的 label。属于原则 5（失败可见）。

**证据**
直接写 `status.label` 的位置：2543（请先打开影片）、2924（导入失败）、2958（请先选中图片图层）、4478（图片导入失败）、7486（没有可撤销）、7499（没有可重做）。`render()` 8214 每帧把 `status.label` 重新赋值为 `statusMessage` 或默认文本，所以这些直接赋值最多存活 0 帧。

**第一性修复**
全部改成 `setStatus(...)` 或新的 `notifyError(...)`；`notifyError` 同时写日志和持久错误条（不会 1 秒消失）。加一个静态检查/测试：禁止在 `UICompositorPanel` 里直接给 `status.label` 赋值。

#### P0-5 空预合成/循环预合成的提示文字会进导出

**现象**

**为什么难受**

#### P0-6 “替换所选轨道素材”实际会插入一个新图层

**现象**
我在左栏“素材”页点“替换所选轨道素材…”，在素材库里双击一张图；结果多了一个新图层，原来那层没变。素材库底部的“替换当前图层”按钮又是另一套行为。

#### P0-7 导出对话框的“一键 1080p60”会覆盖用户刚选的设置

**现象**

#### P0-8 撤销粒度是 1 秒定时器，不是用户动作

**现象**
我删了一个图层，马上按 Ctrl+Z，结果把前一秒的另一个修改也一起撤了；如果我等两秒再按，可能只撤销删除。每次撤销退多远，取决于我按得多快。

**为什么难受**
在 Premiere 里，Ctrl+Z 精确回退一个动作，Edit 菜单还会告诉你动作名。这里撤销是不可预测的，用户不敢依赖它。

**根源**
可逆性粒度与动作粒度不一致。属于原则 4。

**证据**
`captureSnapshot` 7447–7480 每帧调用、1 秒节流；`undo` 7482 直接 pop 最近快照。`trackTimeline.isInteracting()` 只排除轨道拖动，不排除其它连续操作；快照不区分“动作开始/结束”。

**第一性修复**
在每个公开命令的**入口**调用 `beginAction(name)`：如果当前状态与 `lastSnapshot` 不同，先把 `lastSnapshot` 压栈，再执行；连续拖动由 `beginAction/endAction` 包住，只在结束时压一次。撤销栈存 `{name, json}`，UI 顶部加 Undo/Redo 按钮，撤销时显示“已撤销：删除图层”。这是中等改动，但它决定了用户敢不敢用。

### 4.2 P1：主工作流被切断

#### P1-1 预合成在轨道上不像容器，进出路径不对称

**现象**

**为什么难受**

**根源**
容器没有形状，进出不对称。属于原则 3。

**证据**
`renderLaneRow` 609–691 只画 bar/文字/FX 徽章；`barColor` 1373 给 precomp 一个橙色；`typeIcon` 1389 用 STRUCTURE；`precompBack` 1949–1952 是 20px 图标；Esc 分支 7606–7641 没有 precomp。

#### P1-2 进入预合成丢失上下文（时间、缩放、父播放头）

**现象**

**为什么难受**
Premiere 的每个序列有自己的播放头；进入嵌套序列会定位到对应时间，缩放也各自保留。这里所有合成共用一个 `time`，进入/退出都 `fit()`。

**根源**
没有 per-comp 视图状态；进入时没有把父时间映射到子时间。属于原则 1 + 原则 3。

**证据**
`enterPrecomp` 4943–4950：`this.time = 0F; this.trackTimeline.fit();`；`exitPrecomp` 4969–4980 恢复父 time 但仍 `fit()`。

#### P1-3 没有合成浏览器：不能切换/新建/重命名/删除合成

**现象**

#### P1-4 轨道上的关键帧刻度是装饰，点了会拖走整段素材

**现象**

**证据**

#### P1-5 关键帧抽屉在轨道下方，打开时轨道只剩 2–3 条

**现象**
我一点“秒表”，底部就弹出关键帧抽屉，轨道区一下从 4 条轨变成 2 条；我正在看的那条被挤出去了。

**为什么难受**

**根源**

#### P1-6 选中关键帧会覆盖整个右栏，Effect Controls 消失

**现象**
我点了一个关键帧，右侧整个“效果控件”突然变成了另一套属性面板；我把底部关键帧抽屉关掉，这层属性面板还在，原来的效果栈回不来。只有切到另一条轨道再切回来，右栏才恢复。

**根源**

**第一性修复**
不要把 `target` 设为整个 inspector。用一个专门的窄条（例如抽屉右侧 160px）或就地浮层承载关键帧属性；如果坚持用右栏，加一个页签头“关键帧 @ 00:00:03:12”和“返回效果控件”按钮，并在选中时高亮对应的属性行。

#### P1-7 效果栈不是“栈”，折叠后连开关/排序/删除都没了

**现象**
5 个效果展开就是 5 段长参数，要滚好几屏；我把效果折叠起来想看看顺序，结果连启用开关和上移/下移/删除都不见了。

**为什么难受**
Premiere 的 Effect Controls 是“紧凑效果名列表 + 选中项参数”；折叠不会让行级操作消失。这里把行级操作放进了可折叠的 body。

**根源**
列表与参数没有分层；行级操作绑在 body 上。属于原则 7 + 原则 2。

**证据**
`addEffectControls` 5208–5213 为每个 effect 加一个 `UISection`；`effectControlSection` 5886–5917 把 enabled/up/down/remove 放进 `section.fields`；`section.remember(..., true)` 默认展开。

**第一性修复**
在“效果”区顶部加一个紧凑栈列表：每行 = 拖拽手柄 + 启用勾选 + 效果名 + 删除；选中行在下面展开参数。行级操作永远可见；折叠只影响参数。栈列表可拖拽排序，支持键盘上/下、复制/粘贴、重置。

#### P1-8 加效果没有就地反馈

**现象**
我双击一个效果，窗口底部状态栏闪了一句“已添加”，右侧看不出任何变化——新效果追加在长列表最底下，既不滚动也不高亮。

**为什么难受**
Premiere 里新效果会出现在 Effect Controls 顶部/当前选中位置，立即可见。这里“添加成功”的反馈在窗口最底部，离右栏很远，而且右栏可能根本没滚到新效果。

**根源**
反馈位置错误；没有“把新对象带入视野”的动作。属于原则 5 + 原则 2。

**证据**
`applyEffect` 4053–4089 只 `layer.effects.add(effect)` + `refreshInspector()`；没有滚动/高亮/选中状态。

**第一性修复**
加完后：切到效果栈、把新行滚进视野、闪一下、选中它并展开参数；同时在鼠标位置 toast“已添加：高斯模糊”。如果用户当前在别的 tab，切回时保留这个定位。

#### P1-9 调效果顺序只有 16px 上下箭头

**现象**
想调顺序只能点每个效果标题右侧 16px 的小箭头，不能拖；想把最后一个挪到最前面，得点好几次，还要一路滚。

**为什么难受**
Premiere 的效果栈是拖拽排序，还能多选/复制。这里的操作成本与“调整顺序”这个高频动作不匹配。

**根源**
缺少直接操纵；顺序模型没有可视化的列表。属于原则 2。

**证据**
`effectControlSection` 5900–5901 只有 `Icons.MOVE_UP/MOVE_DOWN`；`moveEffect` 5963–5977 一次移一格，`refreshInspector()` 全量重建。

**第一性修复**
P1-7 的紧凑栈列表直接支持拖拽；保留上下箭头作为键盘/无鼠标的备选；加“移到顶部/底部”。拖拽时显示插入线，松手后只重建栈列表，不重建整个 inspector。

#### P1-10 工作区边界和标记看起来能拖/能点，其实不能

**现象**
工作区两端有两条竖线，看起来能拖，但拖它只会移动播放头；时间尺上的黄色标记看起来能点，点了也是移动播放头。要删标记得去右侧“合成”页点一个写着时间码的按钮，点一下就删。

**为什么难受**
Premiere 的工作区就是可拖的，标记就是可点/可右键的。这里画了 handle 却没有 hit test；删除标记的入口又在一个完全无关的 tab 里，而且是“点标签即删除”。

**根源**
绘制与命中测试不一致；破坏性操作伪装成标签。属于原则 2 + 原则 4。

**证据**
`renderWorkArea` 447–488 画 2px accent 线，没有 handle；`renderMarkers` 724–749 画 6px 菱形；`subMouseClicked` 822–882 在 ruler 上只 `beginScrub`；`markerSection` 6820–6829 的按钮 label 是 `timecode + name`，点击直接 remove。

**第一性修复**
工作区两端加 8px 可拖 handle（拖动改 `workAreaIn/Out`，Shift 吸附）；标记点击选中并弹上下文菜单（跳转/重命名/删除），双击在标尺位置添加；删除标记要确认或可撤销。如果这一轮不做，就先把这两处 affordance 去掉，避免“看起来能点”。

#### P1-11 从影片编辑器进入合成器要先过一道工程列表，还会丢播放头

**现象**
我在影片编辑器 8 秒处点“打开影片合成器”，先弹工程列表；我再点“进入合成器”，进去后播放头是 0，不是 8 秒。

**为什么难受**
Premiere 里从序列打开嵌套序列是直接进入，播放头对齐。这里多一步，而且把刚同步好的时间归零。

**根源**
入口路径没有区分“已绑定影片”和“独立打开”；`bind()` 先把 time 设为影片 cursor，随后 `showStartScreen()` → `openProject()` → `bindComposition()` 又把它设回 0。属于原则 6 + 原则 1。

**证据**
`bind` 2129 设置 `time = filmPanel.getCursor()/20`；2163 `showStartScreen()`；`openProject` 2320 → `bindComposition` 2498 `this.time = 0F`。

**第一性修复**
`bind` 在已有 film/replay 时直接进入编辑器，不显示引导页；只有“没有工程/主动切换工程”时才显示。`openProject` 如果是同一个 project/comp，保留当前 time；切换 replay 也保留 per-replay 的 time。

#### P1-12 预览只有“适应”，没有缩放/平移

**现象**
预览永远整幅适配，不能缩放/平移；1080p 的合成在 220–250px 高的区域里，小字和锚点根本抓不准。

**为什么难受**
Premiere 的 Program Monitor 有 Fit / 100% / 缩放比例，也能平移。这里只能看全图，细节编辑只能靠猜。

**根源**
缺少直接操纵的视图状态。属于原则 2。

**证据**
`preview.fitScale()` 1106–1109 只做 `min(w/compW, h/compH)`；没有 zoom/pan 字段；`subMouseScrolled` 7567–7581 的 Alt+滚轮是时间轴缩放。

**第一性修复**
加 `previewZoom` / `previewPanX/Y`；预览工具条加 Fit / 100% / 缩放百分比；空格+拖动平移，滚轮缩放（只在预览内）；所有命中测试用同一套 `screen ↔ comp` 变换。这样 P1-13 的蒙版/形状编辑才有基础。

#### P1-13 蒙版和形状只能在右栏输数字，画面上没有可拖的点和手柄

**现象**
加一个矩形蒙版，得到一个默认的整层矩形；想改形状，只能在“蒙版”页输入“点1 X / 点1 Y / 入点1 X / 入点1 Y / 出点1 X / 出点1 Y……”；画面上看不到蒙版轮廓。形状的贝塞尔路径也一样。

**为什么难受**
Premiere/AE 的蒙版是钢笔工具直接在画面上画的；这里是“用数字描述一个图形”，用户的意图（画一个圈）和界面给的路径（输 6 个数字 × N 个点）之间落差极大。

**根源**
缺少直接操纵；数值字段成了唯一入口。属于原则 2。

**证据**
`maskSection` 6643–6724 每个 mask 点 6 个 `animatedNumberRow`；`shapeSection` 6530–6641 每个 shape 只有数值字段；预览的 `renderSelection` 只画图层四角，没有 mask/shape 叠加。

**第一性修复**
第一步（小）：在预览里画出选中图层的蒙版/形状轮廓和点，让数字字段有可视对应。
第二步（中）：加蒙版/形状叠加编辑——点选、拖动点、拖贝塞尔手柄、双击加点、Delete 删点、闭合路径；数值字段保留为精确输入。
第三步：加钢笔/矩形/椭圆工具，支持在预览里直接画。

#### P1-14 右侧检查器太矮，且“片段”占据了最宝贵的位置

**现象**
在 1080p、GUI scale 2 下，右侧只有 220–250px 高；一选中图层，真正占高度的是“运动”的 9 行和默认展开的“运动模板”4 行，效果区被推到折叠线以下；加完效果要滚很久。“片段”本身默认是折叠的（只占一行标题），但它仍然排在最前面。

**为什么难受**
Premiere 的 Effect Controls 顶部是 clip 名 + Motion/Opacity + 效果栈；片段时间在时间轴上改。这里把片段时间段放在最上面（即使折叠也占位），运动模板又默认展开，把真正的效果推下去。

**根源**
信息架构与布局：面板高度被全宽时间轴压缩；优先级排序错误。属于原则 7 + 原则 2。

**证据**
`applyLayout` 4239–4242：`bodyHeight = area.h - 24 - timelinePanelHeight - 18`；1080p/scale2 下约 248px。`fragmentSection` 5262–5361 的 `remember(..., false)` 默认折叠；`motionSection` 5363–5433 有 9 行；`motionTemplateSection` 5439–5479 原来 `remember(..., true)` 默认展开 4 行按钮。`addEffectControls` 的顺序是 fragment → motion → motionTemplate → opacity → effects。

**第一性修复**
短期（本轮已做）：把“运动模板”默认折叠；在顶部加当前图层名；效果控件仍保持 fragment → motion → templates → opacity → effects。
短期（可继续）：把运动模板移到效果栈之后，或把“运动”默认只展开位置/缩放；把 clip 名固定在顶部不随滚动消失。
结构：把时间轴从“全宽”改成“左下”，右栏从顶部一直延伸到面板底部（类似 Premiere 的 Effect Controls 高度），这样右栏能多出 250px。

### 4.4 这些是好的，修复时不要动

- **效果库**：搜索、分类、最近使用、双击应用——信息架构是对的，问题只在“目标不可见”和“应用后没反馈”。
- **预览**：独立 FBO、FX/Mask 对照、BBS 底图、摄像机视图/3D 空间——这是项目的核心差异，不要为了“像 PR”把它换成世界预览。
- **轨道 bar 的 move/trim/snap/右键**：语义正确（`CompLayer` 里统一处理关键帧/标记），保留；要补的是关键帧命中和工作区/标记的 hit test。
- **关键帧用 BBS 原生 dope sheet**：不要自绘菱形/图表；保留 BBS 的插值、复制粘贴、右键菜单。
- **素材库**：缩略图、分类、搜索、音效试听——保留；要补的是替换意图和面板边界。
- **渲染队列模型**：串行、进度、输出预设、失败重试——保留；要补的是选中行、预设下拉、完成通知。
- **引导页**：保留，但只在“没有工程/主动切换工程”时出现，不要让已绑定影片的用户每次先过一道列表。
- **绝对布局 + 拖拽分栏 + 尺寸持久化**：保留；要补的是响应式约束（最小宽度/高度、tab 横向滚动）。

## 5. 修复蓝图（第一性原理）

### 5.1 布局：把时间轴从“全宽”改成“左下”

当前所有问题的共同物理原因之一，是**时间轴横跨整个窗口**：

- 右栏被压到 220–250px，效果栈和关键帧属性都放不下；
- 关键帧抽屉只能塞在轨道下面，和轨道抢高度；
- 用户点关键帧时手在左下，编辑面在右中/底部，视线要跨越整个屏幕。

第一性修复不是“把抽屉做小一点”，而是**让右栏从顶部一直延伸到面板底部**：

```
┌──────────────────────────────────────────────────────────────┐
│ 面包屑：主合成 / 预合成 3      [合成 ▾]   [撤销][重做] [导出] │
├───────────────┬───────────────────────────────┬──────────────┤
│ 效果库/素材/  │ 预览                          │ 效果控件      │
│ 合成          │                               │ （全高）      │
│               │                               │              │
├───────────────┴───────────────┬───────────────┤              │
│ 时间轴（轨道 + 行内关键帧）    │ 关键帧/属性   │              │
│                               │ （上下文栏）  │              │
└───────────────────────────────┴───────────────┴──────────────┘
```

- 时间轴宽度 = `panelWidth - rightPanelWidth - gap`，不再压到右栏下面。
- 右栏高度 = 整个 body，效果栈至少多出 250px。
- 关键帧上下文栏放在“轨道右侧的空白区域”，和点击的轨道行垂直对齐；选中关键帧时就地出现，不选中就收起。在 960px 宽的逻辑窗口里，它可以是**浮层/抽屉**，不必是固定的第四列；关键是它出现在鼠标附近，而不是页面另一端。
- 这是最小可行的“就近反馈”布局；不需要重写渲染。

### 5.2 容器：预合成/合成浏览器/面包屑

1. **轨道上的 precomp 行**：disclosure 三角 + 子层数 + 首帧缩略图；hover 出现“进入”；双击/回车进入。
2. **面包屑**：`主合成 / 预合成 3 / 预合成 1`，每段可点；右侧显示当前 comp 尺寸/时长。
3. **合成浏览器**：左栏“合成”tab，列出所有 comp（名称/尺寸/时长/引用数），支持新建/重命名/复制/删除/拖到时间轴。
4. **退出**：Esc/Backspace、面包屑、轨道行上的“返回父级”三选一；不要只留一个 20px 图标。
5. **每 comp 视图状态**：`Map<compId, {time, zoom, scrollY}>`；进入映射父时间，退出恢复。
6. **预合成操作**：原索引插入、子层时间归零、关键帧平移、父子/遮罩关系显式处理（P0-1）。

### 5.3 关键帧：一个对象、一个时间、一个编辑面

1. **轨道刻度变成真关键帧**：命中 → 选中 + 播放头对齐 + 可拖动时间 + 右键插值 + 双击就地编辑。
2. **就地编辑器**：在轨道右侧/关键帧旁显示一个小卡片：时间、值、插值、Easy Ease、删除。字段少而精，不覆盖整个右栏。
3. **右栏值编辑器与选中键统一**：有关键帧选中时，属性行显示“关键帧 @ 3s”，写入该键；没有选中时按播放头写，并显示 auto-key 状态。
4. **抽屉降级为“全部属性总览”**：不自动打开；打开时保证至少 3 条轨道可见；选中键自动滚入视野。
5. **插值/缓动**：轨道右键、抽屉右键、快捷键三处都能到；至少加 Easy Ease（F9 或 Ctrl+Shift+F9）。

### 5.4 效果栈：紧凑列表 + 拖拽排序

1. 效果区顶部固定一个紧凑列表：`[拖拽手柄] [启用] 效果名 [删除]`；顺序一眼可见。
2. 选中行在下面展开参数；折叠只影响参数，不影响行级操作。
3. 拖拽排序 + 键盘上/下 + 移到顶部/底部；复制/粘贴效果；重置参数。
4. 加效果后自动滚到新行、闪烁、选中；鼠标位置 toast。
5. 样式用同一套列表；左键“添加样式”打开菜单；样式可排序。
6. 多选图层（至少 Shift/Ctrl 在轨道头上）批量应用/粘贴效果。

### 5.5 反馈、撤销、状态

1. **禁止直接写 `status.label`**；统一 `setStatus` / `notifyError`。错误要持久、可关闭、带“打开日志”。
2. **动作级撤销**：`beginAction(name)` / `endAction()`；拖动只在结束时压栈；Undo/Redo 按钮 + 动作名。
3. **删除可逆**：图层/效果/样式/预设删除都进撤销栈；必要时二次确认。
4. **保存状态**：标题加 `*`；保存按钮显示“已保存”/“保存中”；统一 `markDirty()`。
5. **就地反馈**：加效果/加图层/替换素材在动作附近 toast + 滚动/高亮；失败在控件旁显示红色提示。

### 5.6 单一真相与意图保真

1. `layer.in/out` 只有一个写入口（`trimInTo/trimOutTo`）；图层页不再直接赋值。
2. 网格/安全框/自动保存/预览背景只留一个编辑器；另一处只读。
3. 导出只有一个入口/一个“开始导出”；分辨率/帧率/时长/输出路径在同一张表单里，不存在隐藏覆盖。
4. `+` 左键打开类型选择；`替换素材` 进入替换模式；`添加效果…` 弹出效果选择器。
5. 混合语言/枚举数字框统一：中文、下拉/分段、错字修正。
