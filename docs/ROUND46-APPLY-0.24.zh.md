# Round 46 — 应用 0.24 修复版源码（v0.24）

用户提供了一份 `bbsae-0.24-source-modified.zip`（在他们那边已经改好的 0.24 源码）。
本轮把这个修复版**完整应用**到本仓库，逐处核对它到底修了什么，并在应用过程中用
第一性原理把这份源码里仍然存在的 3 个缺陷一并修掉。

## 1. 应用方式

- 以 zip 内的 344 个文件为准覆盖工作区（保留仓库自己的 `libs/.gitkeep`；依赖 jar 不入库）；
- 逐文件比对：`260` 个文件内容相同、`68` 个不同、`16` 个新增；
- 语义变更 35 个文件（另有一些只是换行符差异），新增文件：
  `IrisColor`、`TrackerEngine`、`CompTracker`、`TrackerMatcher`、`CompTransformHandles`、
  `CurveInteraction` 以及 9 个新测试。

## 2. 这份源码修了什么（0.23 + 0.24，来自 CHANGELOG 与代码核对）

### 效果「不生效」类

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| 波浪变形 / 置换图 / 湍流置换不动 | DISTORT 着色器的位移是图层像素，却被额外除以 `LayerSize` 再走 `localDeltaToComp`（其列向量本身就是"合成像素/图层像素"），48 px 位移实际 ~0.1 px | 直接 `uv += localDeltaToComp(offset)` |
| 3D 图层在代理分辨率下效果尺寸漂移 | `scaleEffectForRaster` 对"着色器内部已按图层像素换算"的参数又乘了一次缩放 | 只缩放真正的像素半径（模糊/阴影/描边等），DISTORT/PIXEL/生成器尺寸不再二次缩放 |
| 分形杂色不像特效 | 归类在「生成」，噪声域按归一化 UV 计 | 移入「噪点与颗粒」，噪声改图层像素空间（缩放 = 特征尺寸），演化改为逐八度旋转噪声域（AE 的 Evolution），幅度归一化 |

### 绿幕抠像（问题 4 / 5）

- 旧算法用 RGB 距离：**同色相不同亮度**的像素（打光的绿幕、偏黄绿）距离仍在容差内，
  于是留下一层浅透明绿幕；叠在后面的模糊/辉光又把绿边混回画面。
- 新算法：色度轴 `(r-y, b-y)` 上的**色相差 + 饱和度门控**，亮度解耦；新增
  **蒙版黑场/白场**两个清理滑杆（默认 0/1，老工程行为不变）；**溢色抑制**只在
  `matte<1`（屏幕色仍有影响）的像素上压绿，完整保留的主体绿色不动。

### itrp / iterationRP 黑屏（问题 3）

- 根因一：itrp 的 final pass 写 `vec4(color, 0.0)`，世界帧捕获是逐字节拷贝，
  消费方按纹理 alpha 混合 → 整帧不可见。现在每次捕获后跑一个 `OPAQUE` 全屏 pass
  （`ShaderSources.OPAQUE`）把 alpha 归一为 1，同时洗掉其它包写入的 alpha 垃圾；
  该 pass 完整保存/恢复 framebuffer、viewport、blend、depth、scissor、cull、color mask、program。
- 根因二：`IrisFinalizeMixin` 在某些 Iris 结构变化下绑不上，旧逻辑回退到"合成前主 framebuffer"= 黑。
  新增 `IrisColor` 反射读 Iris 的 `colortex0` 作为回退捕获（未 tonemap，但至少是真实画面），
  预览信息行显示 `光影最终帧` / `光影帧（回退 · 合成前颜色）` / `光影帧未捕获`。

### 蒙版卡顿（问题 2）

- 2D 图层、调整层、轨道遮罩层的蒙版统一按**渲染分辨率**栅格化（与 3D 烘焙路径一致）：
  蒙版纹理与内容 FBO 同 UV 采样，信息量不变，动画蒙版不再每帧跑整幅 1920×1080 的 CPU 路径 + 盒式模糊。

### 点跟踪器（问题 6，新功能）

- `CompTracker`（锚点 / 模板半径 / 搜索半径 / 置信度 / 帧范围 / 采样）
  + `TrackerMatcher`（纯 Java NCC 模板匹配，含单元测试）
  + `TrackerEngine`（每显示帧协作式分析一帧；含 BBS 世界层时先寻帧再分析）。
- 检查器「跟踪器」区：新建 / 开始分析 / 停止 / 应用到位置 / 清除 / 删除。
  「应用到位置」把每帧位移写成所选图层的独立 X/Y 通道关键帧；表达式新增
  `tracker.<id>.x` / `.y`（当前帧跟踪位置，可驱动效果参数或蒙版点）。

### 曲线编辑器手柄

- 旧的镜像只镜像斜率并保留各自半径：两杆长短悬殊时，纵向拖一下对侧手柄会放大几十上百倍飞出。
- 现在改为**真正的对称镜像**（等半径、方向取反），镜像半径按对侧相邻段长钳制；Alt 拖动断开镜像。
  只有真正参与贝塞尔段的手柄才显示/可抓，密集曲线取最近的手柄，拖动基于按下时快照。

### 0.23 的其余项

- 帧缓存异步写 + 临时文件原子落盘；缓存键补上工程 ID 与实体/回放参数；时间轴不再每帧复制图层列表。
- 图层库卡片自适应 1–3 列（最小 230 px），中文描述按真实字宽换行。
- 预览边柄只缩放对应轴、角柄默认等比（Shift 自由），3D 图层用鼠标射线与图层平面求交定位；
  边柄显示水平/垂直缩放光标。
- 更名 **BBS AE**（模组 id 仍为 `bbsae`），首席赞助者更新为 **【星辰久梦君_Star Dm Sov】**（金色）。

## 3. 应用时发现并修掉的 3 个缺陷

应用后跑全量测试，出现 **5 个失败**，逐一按第一性原理定位：

1. **`generate` 着色器编译失败（真 bug）**
   `ShaderSources.GENERATE` 的分形杂色分支引用了 `luv`，而该着色器里只有 `uv`
   （`luv` 是 DISTORT 着色器的变量，被复制过来了）。后果：`generate` 程序链接失败 →
   分形杂色与渐变生成器回退/黑屏，并让随后的 `invert` 测试残留 `GL_INVALID_VALUE`。
   修复：`vec2 p = uv * LayerSize / ...`。
2. **`CompTracker.sampleAt` 超出范围时夹取（真 bug）**
   文档写的是"范围外返回 null"，实现却夹到首/尾采样：表达式 `tracker.<id>.x` 在分析范围外
   会永远停在最后一帧的位置，而不是回落到用户放的锚点。修复：范围外返回 null。
3. **`CompCurvesTest.mirroredHandlesFollowRadiusSymmetrically` 期望值写反（测试 bug）**
   左杆向量 (8, −6) 关于关键帧镜像应为 (+6)：与实现、文档（"等长、精确取反"）都一致，
   测试却断言 −6。修复测试期望并在注释里写明方向关系。
