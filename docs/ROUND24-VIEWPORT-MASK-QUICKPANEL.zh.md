# Round 24 — 视口控制、图层空间效果、蒙版/排除、效果缩略图、轨道侧快捷面板（0.13.0）

> 这一轮的五条需求都指向同一个方法论：**先问"这个东西属于谁"**。
> 视口输入属于窗口，不属于 BBS 的事件分发；效果属于图层像素，不属于合成画面；
> 蒙版属于两个图层的集合运算，不属于舞台；关键帧属于图层属性，不属于检查器底部。

## 1. 3D 视口"操作不了、只能固定视角"

### 1.1 根因

导航完全建立在 `subMouseClicked` 上。BBS 的 `UIElement.mouseClicked` 会先分发给子元素，但
**右键还会同时触发上下文菜单**，而且不同控件对非左键的处理并不一致。于是：

* 右键拖动：事件被别的路径吃掉，视口收不到；
* 中键：很多笔记本根本没有中键；
* 结果就是"只能看，不能动"。

把输入挂在 UI 事件上，是把"窗口的物理状态"托付给了一个不保证转发的层。

### 1.2 修法：每帧直接读鼠标状态

`pollViewportInput()` 在预览元素 `render()` 的最前面运行，直接读 GLFW：

```java
boolean right  = Window.isMouseButtonPressed(1);   // GLFW: 1 = 右键
boolean middle = Window.isMouseButtonPressed(2);   // GLFW: 2 = 中键
```

* 指针在预览区内且按键从"抬起"变"按下" → `beginViewportDrag(ORBIT / PAN)`；
* `Shift` 决定平移；按下瞬间若在看穿摄像机状态，先退出看穿（Blender 的 numpad-0 行为）；
* 事件路径仍然保留（`subMouseClicked` 消费 1/2，避免同一帧弹出上下文菜单），但**不再是唯一入口**；
* `beginViewportDrag` 增加"已在拖拽则忽略"，防止轮询和事件重复触发导致起点被重置。

这样即使 BBS 吞掉右键，视口照样能转。

## 2. 渐变随视角变化

### 2.1 根因：效果被放在合成空间里执行

`EffectSpace.of()` 对 3D 图层返回**合成空间**（注释写着"3D 图层的屏幕足迹不再是本地矩形"）。
这在"把图层栅格化到合成尺寸"的管线里是自洽的，但它把**效果的坐标系**绑到了**画面的坐标系**：
摄像机一动，渐变在图层上就滑走了。

第一性原理：**效果是图层像素的属性**。AE 也是先做效果、再做变换。合成空间只是当时实现
"在哪里栅格化"的副产物。

### 2.2 修法：两边都改成图层空间

* **视口**（上一轮已做）：源纹理在图层本地空间栅格化，效果用
  `EffectSpace.ofBounds(layer, world, ctx, rect…)` 烘焙进去。
* **成片管线**（本轮新增）：3D 图层若带效果，`renderBaked3D()` 取图层空间栅格
  （`CompLayerSourceCache`，已含效果），再按 `model · projection` 用 **8×8 网格**贴到合成上
  （每格两个三角形，仿射 UV 在格子内近似单应，误差远小于 1px）。
  该图层的效果 pass 被跳过，避免二次施加。

于是**草稿、看穿预览、导出**三处的渐变都锁在图层上。

## 3. 蒙版（交集）与排除（差集）

### 3.1 语义

| 操作 | 数学 | 含义 |
| --- | --- | --- |
| 蒙版 | A ∩ B | 只显示形状覆盖到的部分 |
| 排除 | A − B | 只显示形状没覆盖到的部分 |

形状来自**另一个图层**（Alight Motion 的做法：形状放上面，选中它，点遮罩）。实现复用已有的
轨道遮罩（`trackMatteId/Mode`）：`ALPHA` = 交集，`ALPHA_INVERTED` = 差集。

### 3.2 交互

图层检查器顶部新增一行：

```
用作蒙版（交集）   用作排除（差集）
```

点击后：

1. 目标是**它下面那一层**（图层列表 index 0 是最底，所以"视觉上在下面"是 `index-1`）；
2. 形状层自动 `guide = true` + `visible = false` —— 否则它的填充会盖住它本该露出的区域；
3. 状态栏说明，检查器显示"当前：<形状层> · 蒙版"和"清除蒙版"。

### 3.3 草稿里的实现

视口不做合成，只贴四边形，所以在**源纹理构建时**做集合运算：把形状层的栅格按两层的相对矩阵
画进目标层的栅格，用目标色的"destination in source"混合：

```glsl
mask:    glBlendFunc(GL_ZERO, GL_SRC_ALPHA)          // dst *= src.a
exclude: glBlendFunc(GL_ZERO, GL_ONE_MINUS_SRC_ALPHA) // dst *= 1 - src.a
```

相对矩阵 `inv(W_target) · W_matte` 把形状层的本地坐标映射到目标层本地坐标（2D 时是仿射，精确）。
指纹里额外混入两层的位移/旋转/缩放和形状层的内容签名，改任何一边都会重建。

## 4. 效果库：每个效果自己的预览图（Alight Motion 式）

参考 AM 的 Effect Browser：分类 + 搜索 + **每个效果展示它自己的画面**（而不是图标）。

实现：

* `CompEffectPreview.frame(type)` 本来就为"效果控件"渲染 96×54 的测试卡（渐变带 + 白圆 + 三色条
  + 暗角），按 `(类型, 参数)` 缓存；
* 效果库列表把每行左缩进改为 26px，在缩进里画 16×16 的缩略图；
* 行几何用列表自己的 `visible()` / `areaOf(i, cell)`，**并按 `scroll.getScroll()` 校正**——
  `areaOf` 返回的是内容坐标（x 从 0 开始），第一版直接用它在面板外画，什么都看不见；
* 只有可见行才取图，滚动时才生成新图，所以 100+ 效果不会卡。

## 5. 轨道右侧的图层快捷面板

### 5.1 为什么

给图层 K 一个位移，要在检查器里滚到最底部改 X/Y，再回时间轴打关键帧——每个关键帧三次上下文切换。

### 5.2 结构

新 `UILayerQuickPanel`，停靠在时间轴右侧，宽度与左侧轨道头相近（默认 210，可拖 160–340，存
`settings.quickPanelWidth`）：

```
3D Camera
X   [ 748.8 ] ◆
Y   [ 561.6 ] ◆
Z   [ 1158  ] ◆
旋转 [ 0     ]
缩放 [ 100   ]
不透明度 [ 100 ]
◆ = 打关键帧
```

* 数值用 `UITrackpad`（可拖可输），写入走与检查器相同的 `setTransformComponent` / `setScalar`；
* `◆` 调 `addTransformKey` / `addScalarKey("z")` / `addOpacityKey`；
* 只有选中图层时出现，出现时时间轴宽度自动减去面板宽度（`applyLayout`），不需要覆盖轨道；
* 选中/播放头变化才回填数值，正在输入时不会被覆盖。

## 7. 已知限制

* **草稿（3D 视口）暂不显示蒙版**：成片/看穿摄像机/导出都正确应用，草稿里的实现会在源纹理上
  产生噪点（两层栅格尺寸不同，采样映射不精确），因此先关掉（`CompLayerSourceCache.DRAFT_MATTE`），
  宁可"草稿不显示"也不显示错的像素。按 0 看穿即可看到真实结果。
* 蒙版按**图层 alpha**计算（交集/差集）；亮度蒙版（luma）在成片里仍可用。
* 效果缩略图是**静态帧**（AM 是动画的）；参数变化会重新渲染，但不会自己播放。
* 快捷面板只做法线属性；曲线/表达式仍在检查器里编辑。

## 附：0.13.1 —— "右键拖动仍然不能环绕"的补充定位

实测日志证明**输入与渲染都是通的**：一次运行里 26 次 `viewport input: drag start mode=10 button=1`，
yaw 从 31 连续变到 -1058，图层投影矩形跟着变。也就是说"不能环绕"不是输入没到，而是**用户当时不在 3D 视口**：
2D 编辑视图与 3D 草稿都铺满预览，看起来一样，但 2D 下的右键只是 BBS 的上下文菜单。

0.13.1 的做法是让这个手势**在任何视图里都成立**：

* 2D 编辑视图里右键拖动 → 自动 `enter3DSpace()` 并开始环绕；
* 3D 草稿里：右键/中键 = 环绕，左键拖**空白处**（或 Alt+左键）= 环绕（笔记本没有中键也能用）；
* 键盘兜底：A/D 偏航、W/S 俯仰、Q/E 推拉（Ctrl 加速）；
* 2D 视图右下角常驻"2D 编辑视图 · 右键拖动进入 3D 视口"，不再靠猜。

验证：`-Dbbsae.debugViewport=true` 会打印每次拖动的开始/结束与按钮；
`-Dbbsae.debugOrbit=<度/帧>` 可在不碰鼠标的情况下让画面转起来（用来分离"输入问题"与"渲染问题"）。

## 附二：0.13.2 —— 3D 图层渐变"颜色颠倒"的真因（UV 上下角写反）

### 现象

3D 图层（`threeD = true`）带渐变时：草稿里颜色正确，**看穿摄像机/导出里渐变上下颠倒**。
横向渐变看不出来，所以之前几轮都没暴露；换成纵向或斜向渐变（角度 90/45）就非常明显。

### 定位

`renderBaked3D` 把图层空间栅格按格子画到合成上时调用 `Batcher2D.texturedBox`。
它的 UV 参数是**两个角**，顺序与四角一致：`(u, v)` 是左上、`(uw, uh)` 是右下。
代码传成了 `(u0, vBottom, u1, vTop)` —— 左上角给了"底部"的 v，于是整张贴图垂直翻转。

`layerUv()` 的约定可以反推：`vz = (inv.m11·compH + inv.m31 − by)/bh`，而 `compY = (1−vUv.y)·compH`，
所以图层局部 v 是 **y 向下**（0 在上）。角度 90 的 `t = uv.y` 在顶部为 0 → 顶部应是 ColorA。
实测（`gradV-look`）修复后顶部为红（ColorA），与草稿一致；修复前则是红在底部。

### 修复与回归工具

* `texturedBox(..., u0·texW, **vTop**·texH, u1·texW, **vBottom**·texH, ...)`；
* 新增两个调试视图，专门给渐变做 A/B：

```
runClientView -PbbsaeView=gradtest    # 单层渐变 + 摄像机，进自由视口（草稿）
runClientView -PbbsaeView=gradlook    # 同一场景，看穿摄像机（成片）
```

场景是 **3D 图层 + 角度 90**（纵向渐变），因为纵向才能暴露上下翻转。
两张截图：`docs/verify/gradV-draft.png`、`docs/verify/gradV-look.png` —— 都是上红下蓝。
