## 1. 构建环境：路径必须纯 ASCII

本轮遇到并已定位一个**会阻断接手**的环境问题：

- 工程副本路径 `C:\Users\Administrator\Desktop\bbsae - 副本 (3)` 含空格 + 中文。
- 现象 1：`GRADLE_OPTS=-Djava.io.tmpdir=<含空格路径>` 被空格切断，报 `Unrecognized option: -`。
- 现象 2：Gradle 测试 worker 启动后 0.002s 结束，报
  `Could not execute test class dev.bbsae.*`，原因是 worker 的 `@classpath` 参数文件里写的是
  真实中文路径，worker JVM 用不同编码读取导致类路径失效。
- ASCII 目录联接（junction）只能绕过一半：Gradle 会把联接解析回真实路径，测试 worker 依旧失败。

**结论：构建/测试请在纯 ASCII 路径下跑。** 原始工程 `C:\Users\Administrator\Desktop\bbsae` 满足条件，
在那里 `cleanTest test` 实测：

```
tests="14" skipped="0" failures="0" errors="0"
tests="2"  skipped="0" failures="0" errors="0"
```

编译（`compileJava`）在中文路径下是可以成功的，只有测试 worker 不行。

## 6. 过程中确认的两个"非 bug"坑（写测试/做夹具时必看）

1. **面板会在 `bind()` / `onDisappear()` 自动 `save()`**
   客户端运行时直接改 `run/config/bbsae/projects/*.json`，会在退出时被内存里的旧数据覆盖。
   做夹具要"先关客户端，再改 JSON，再启动"。

2. **图层有关键帧时，扁平字段 `x/y` 不生效**
   `CompLayer.transformAt()` 一旦检测到 transform 通道有关键帧，就返回插值结果，
   忽略 `layer.x/y`。复制既有图层当模板时会把 `transformData` 一起复制过去，
   于是新图层看起来"位置没生效"。做程序化夹具时必须清空 `transformData` / `opacityData` / `channels`。
