# bbsae 与专业合成器的差距分析

> 对比对象：Adobe After Effects 2026（行业基准）、[EffectCraft](https://github.com/storytold/effectcraft)（开源 clean-room 重实现，自称覆盖约 91% 的 AE 功能宽度、约 45% 的"可用于真实工作"程度）。
> 本文只做差距判断，不改代码。bbsae 的能力按当前源码逐项核对（2026-10-18，中文版 jar）。

---

## 0. 结论先说

**bbsae 现在是一个"流程完整、深度不足"的屏幕空间 MG 合成器。**

- 功能宽度大约是 AE 的 **20%**（效果 42 / 306，混合模式 13 / 38，图层类型 11 / 约 16，无 3D 图层/摄像机/灯光）；
- 对 BBS 创作者的可用度大约是 **35–40%**：标题、HUD、信息图、简单转场都能做，但做不出"有质感的动效"；
- 真正卡住的不是"少 260 个效果"，而是四件事：**运动模糊、速度曲线、表达式、生产效率（撤销/素材库/快捷键）**。

EffectCraft 走的是"把 AE 整个重写一遍"的路线（306 效果、38 混合、JS 表达式、木偶、Lottie、纯 Rust 编码器）。这条路线对我们没有参考价值——bbsae 的定位不是替代 AE，而是**BBS 影片的屏幕空间合成层**。我们应该用 BBS 独有的摄像机/深度/ObjectID 去做 AE 做不到的事，而不是去追它的效果数量。

## 2. 真正拉开差距的 8 件事

按"对成片质感的边际收益 / 实现成本"排序，不是按功能表长度。

1. **运动模糊（Motion Blur + 快门角）**
   现在任何位移/缩放都是"逐帧硬切"，一眼就是游戏 UI。AE/EffectCraft 默认开启。
   实现路径：`CompLayer` 加 `motionBlur`/`shutter`，渲染时按快门时间采样 4–8 个子帧做加权累积（我们已有 FBO 池，成本可控）。

2. **速度曲线 + Easy Ease + 连续贝塞尔**
   我们现在只有值曲线。用户调不出"先快后慢"的手感，只能盲调贝塞尔手柄。
   实现路径：沿用 BBS 图表编辑器，增加速度视图；给关键帧加 `easyEase` 命令（F9）；BBS 的 `Interpolations` 已有多条曲线，可以先接上。

3. **表达式太弱**
   `loopOut()`、`wiggle(2,30)`、`thisComp.layer("标题").transform.position`、`if/else`——这些是 MG 的日常。
   实现路径：把 `CompExpression` 从"四则运算 + 函数白名单"升级为一个小型解释器（变量、成员访问、条件、数组），并给图层属性暴露只读上下文。

4. **全局撤销**
   现在误删图层/改错参数只能靠 20 秒自动保存和 `.bak`。这是"敢不敢用"的问题。
   实现路径：在 `UICompositorPanel` 的操作入口做命令栈（快照式即可，工程 JSON 不大）。

5. **素材库 + 拖放**
   现在图片只能"导入一张、替换一次"。做 20 个图层就要导入 20 次。
   实现路径：`CompStore.assetRoot` 已经是按工程分目录，补一个可复用的素材面板 + 拖到预览/时间轴。

6. **效果广度里的四个高价值缺口**
   - **Time**（Echo / Timewarp）——拖影、残影、节奏感；
   - **Channel**（Shift Channels / Set Matte / Compound Blur）——做遮罩联动；
   - **Simulation / 粒子**——MG 背景与氛围；
   - **Perspective**（Basic 3D / Drop Shadow 已有）——伪 3D 卡片翻转。
   这四类加起来约 15–20 个效果，收益远大于再堆 50 个调色。

7. **文字路径 / 形状 wiggle / offset path**
   标题类项目的高频需求，且都能复用现有 shape/text 光栅化管线。

8. **代理与预渲染**
   4K + 多层蒙版 + 效果时预览会掉到个位数帧率。没有代理，"复杂工程"就只是口号。

## 3. 我们比专业合成器强的地方（应该放大，而不是去补短板）

这几条是 AE / EffectCraft 结构上做不到的：

| 能力 | 现状 | 应该做成什么 |
|---|---|---|
| **摄像机矩阵** | ✅ 绑定相机/回放角色/图层锚点 | 2.5D 视差图层、摄像机驱动的景深、镜头畸变匹配 |
| **场景深度** | ✅ 深度纹理 + 深度遮罩/雾/景深 | **深度引导填充**（圈一块，从更远处采样补洞）、深度调色、深度置换 |
| **Object ID** | ❌ 未接 | **按物体 Shatter / 按物体调色 / 按物体蒙版**——比 2D 猜边界精确一个量级 |
| **世界实时背景** | ❌ 预览是 comp-only | clean scene capture 作为预览底图（P1 待做） |
| **同一时间轴** | ✅ 与 BBS 影片共用播放头 | 合成标记直接吸附镜头切点/音频节拍 |

一句话：**AE 要"从像素反推世界"，我们直接拥有世界。** 差距分析里最该补的不是第 300 个效果，而是把这三条数据（相机/深度/ObjectID）变成 3–5 个"只有 bbsae 有"的功能。

## 4. 建议的补齐顺序

### P0（先把"专业感"做出来，约 2 周）
1. 运动模糊 + 快门角（含图层开关）
2. 速度曲线视图 + Easy Ease 命令
3. 表达式升级：`loopOut` / `wiggle(freq, amp)` / `thisLayer` / 条件
4. 全局撤销/重做
5. 素材库面板 + 拖放替换
6. 快捷键：`A/P/S/R/T/U`、`[` `]` 改入出点、`Ctrl+Shift+D` 拆分图层

### P1（广度与深度，约 1 个月）
7. 效果包：Time / Channel / 粒子 / Perspective（约 20 个）
8. 文字路径、shape wiggle path / offset path
9. 深度引导填充 + ObjectID 通道（BBS 独有）
10. 代理分辨率与预渲染缓存
11. 混合模式补到 20+（HSL 系列、线性光、亮光、实色混合）

### P2（工程化）
12. 2D 点跟踪 / 蒙版跟踪（素材层用）
13. 木偶变形
14. 色彩管理（线性工作流 + LUT）
15. 多输出模块模板、渲染后动作、CLI

### 明确不做
- 完整 3D 渲染器 / C4D 挤出（BBS 自己就是 3D）；
- VR/360；
- 协作/审阅/网络渲染；
- AI Roto（用深度 + ObjectID 替代，更可控）。

## 5. 和 EffectCraft 的定位差异

| | EffectCraft | bbsae |
|---|---|---|
| 目标 | 替代 AE 的独立桌面合成器 | BBS 影片的屏幕空间合成层 |
| 优势 | 306 效果、38 混合、JS 表达式、木偶、Lottie、纯 Rust 编码器、MCP | 摄像机/深度/ObjectID、实时世界、与 BBS 同一时间轴、中文 |
| 劣势 | 太年轻（2026-10 首提交）、Windows/Linux 不稳、无 `.aep` | 效果少、无运动模糊、表达式弱、无撤销 |
| 正确策略 | 追 AE 的功能表 | **不追功能表，追"只有 BBS 能做"的效果** |

如果按 EffectCraft 的路线去补 306 个效果，会陷入"永远差 260 个"的泥潭，而且做出来的东西和 AE 没有区别。把深度和 ObjectID 用起来，才是这个项目存在的理由。
