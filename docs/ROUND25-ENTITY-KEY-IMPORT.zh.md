# Round 25 — 回放实体图层（深度抠像）与系统文件对话框（0.14.0）

> 两条需求看起来无关，其实问的是同一个问题：**这个功能依赖的那条链路，是不是真的由我们掌握？**
> 抠像依赖"这个像素属于谁"，而世界帧里根本没有这个信息；导入依赖"系统对话框会不会出现"，
> 而旧实现把它托付给了一个没有 owner 的原生窗口。两处都回到第一性原理重做。

产物：`bbsae-0.14.0.jar`（711 390 字节）。测试 **182/182**。

---

## 1. 回放实体图层

### 1.1 为什么"用颜色抠像"一定失败

合成器拿到的是一张**成品世界帧**：颜色 + 深度。这张图里没有任何一个像素写着"我属于 3 号回放"。
按颜色抠（绿幕、亮度阈值、边缘检测）在三种情况下必然崩：

* 白盔甲站在白墙前 —— 颜色相同；
* 光影包把整个画面的色调改了 —— 阈值全部失效；
* 实体半透明贴图、发光、受伤闪红 —— 颜色根本不稳定。

需求里的"兼容各种光影"不是"适配每个光影包"，而是**判断依据里不能有颜色**。

### 1.2 第一性原理：身份只能来自几何

唯一稳定的身份信号是**几何**：把选中的回放实体再渲染一遍，只写深度，得到一张"只有这些实体"的
深度图。于是：

```
像素属于实体  ⟺  实体深度 == 世界深度
```

这一条同时解决了三件事：

| 现象 | 深度关系 | 结果 |
| --- | --- | --- |
| 实体正常可见 | 世界深度就是实体写下的那个值 | 相等 → 保留 |
| 方块挡在实体前面 | 世界深度更近 | 不相等 → 抠掉 |
| 未勾选的实体挡在前面 | 世界深度是那个实体的 | 不相等 → 抠掉 |

遮挡不是额外实现的功能，而是深度比较的**副产品**。硬件深度缓冲早就把"谁在前面"算完了，
这里只是把答案读出来。

### 1.3 实现

**深度 pass**（`ReplayEntityMask`）

* 挂在 `WorldRenderEvents.AFTER_ENTITIES`，紧跟在 BBS 画完影片实体之后：
  同一个相机、同一个 pose stack、同一个 transition，几何才会逐像素重合。
* 目标是一张 `DEPTH_COMPONENT24`、与世界帧同尺寸的 FBO；`colorMask(false×4)`、`depthMask(true)`、
  `LEQUAL`，清成 1.0。只写深度，不付着色成本。
* 逐回放调用 `FilmEntityRenderer.renderEntity`，用 `FilmControllerContext.instance.setup(...)`
  传入 BBS 自己的实体表 —— 和影片编辑器画的是同一份数据。
* `FormRenderLast.suspend()` 包住整个 pass：否则 `render_last` 的表单会被推迟到世界之后，
  落不进这张图。
* `paused` 时 transition 取 0（与 BBS 的 `getTransition` 一致），否则实体会比世界帧偏出
  一个 tick 的位置，轮廓上会出现一圈描边。

**抠像 pass**（`ReplayEntityKey` + `ENTITY_KEY` 着色器）

* 一个覆盖图层目标的全屏三角形，用 `inverse(projection · model)` 把片元反投影回图层本地坐标，
  再映射成世界帧 UV。这样图层可以被移动、缩放、旋转、改锚点，抠像跟着走。
* 深度比较在**视空间（方块）**里做，不在 NDC 里做：远平面上 1 个 NDC 单位是几百格，
  NDC 容差要么漏掉整个背景，要么把远处的实体判掉。容差按距离缩放，顺便覆盖 24 位深度量化。
* 羽化 / 收缩作用在**覆盖率**上（对邻域做平均 / 取最小），不是对颜色做模糊 —— 边缘不会带出背景色。
* 输出预乘 alpha，交给管线既有的 un-premultiply 统一还原，避免边缘二次除 alpha 发亮。
* 3D 图层无法抠（matte 是屏幕空间的属性），退化为不抠的世界底板，而不是给一张错的 matte。

**首帧与缓存**

* composition 只有到 frame overlay 才知道要抠谁，而那时世界已经画完。请求因此跨帧携带
  （勾选变化最多晚 16 ms），并在 overlay 处用**保存下来的相机**做一次懒渲染 —— 导出的第 0 帧
  不会缺 matte。
* 含实体图层（或 BBS 预览层）的合成会绕过内容缓存与预渲染缓存：它的像素随影片变化，
  缓存会把它冻住。

**勾选表**

* 一个"抠出所有回放实体"开关 + 每个回放一行复选框。
* 两者不会互相矛盾：在"全部"状态下取消任何一行，会先把当前列表物化成"仅勾选"，再删掉那一行。
  开关只是"全选"的快捷方式，不是第二个真相来源。
* 每行标注"已禁用 / 无形态"，因为这两种回放不会被 BBS 画出来，也就无从抠起。

## 2. 系统文件对话框

### 2.1 根因

BBS 的 `UIFileDialogs` 在工作线程里调用 LWJGL 的 tinyfd。tinyfd 是一个**没有 owner 的原生窗口**：

* 全屏 / 无边框的 Minecraft 窗口可以把它盖住，看起来"点了没反应"；
* 平台拒绝显示时它直接返回 null，回调永远不触发 —— 从游戏的角度看**什么都没失败**。

### 2.2 修法

`NativeFileDialog`：

* 用 `java.awt.FileDialog`（各平台**原生**的打开对话框），带一个 1×1、always-on-top 的 owner frame，
  所以不会被无边框游戏盖住；在工作线程里弹，渲染线程不停。
* **取消 ≠ 失败**：回调是一对 `onPick` / `onUnavailable`。只有 AWT 真的不可用才回落，
  用户按取消不会被当成故障。
* AWT 不可用时回落到游戏内文件浏览器 —— 那条路径永远能导入，不会出现"按钮是死的"。
* 图片 / 视频 / 音频 / 字体 / 素材库五个导入入口全部改走它；浏览器里的"系统对话框…"按钮也换成它。

## 3. 验证

* **像素级**：`ReplayEntityKeyPixelTest` 用合成缓冲区证明四件事 —— 实体被抠出、前方方块把实体挡住、
  收缩真的收边、羽化产生半透明边缘、世界帧没有上下颠倒。着色器不是"编译通过"，而是"读回来的像素对"。
* **实机**：开发客户端里给 `export_test` 影片加一层回放实体，日志显示
  `replays=2 rendered=1`，遮罩覆盖约 15 万像素；把舞台涂成洋红后，画面里只剩抠出来的角色，
  背景完全透明（该洋红只存在于验证截图，未进入代码）。
* **模型**：`CompModelTest` 覆盖"全部 / 仅勾选"两种语义、id 列表的脏数据与复制往返。

测试合计 **182/182**。
