## 1. 混合模式“根本用不了”的根因

混合发生在 `COMPOSITE` shader 里：

```glsl
vec4 b = texture(Backdrop, vUv);
vec3 blended = blendColor(b.rgb, srcRgb);       // ← 旧代码
float outA = a + b.a * (1.0 - a);
vec3 outRgb = (blended * a + b.rgb * b.a * (1.0 - a)) / outA;
```

`blendColor()` 用的是**直通 alpha 的 RGB**，但旧代码没有看 `b.a`。合成背景默认透明，
因此任何 Multiply/Screen/Overlay 图层在空白区域都会和 `b.rgb = (0,0,0)` 相乘 → 变黑；
Screen 则变白。视觉上就是“混合模式一开图层就没了 / 完全不像混合”。

**修复**：混合结果按背景覆盖率在“原色”和“混合色”之间插值：

```glsl
vec3 blended = mix(srcRgb, blendColor(b.rgb, srcRgb), b.a);
```

背景 alpha=0 时结果就是原色（和 AE/PS 在透明画布上的行为一致），只有真正有像素的
背景才参与混合。

**UI**：原来是“点一下循环 13 种模式”的按钮，既看不到列表也无法回退。改成
`UIChoiceButton<Integer>` 下拉，列出 13 个中文模式名；选择即写入并保存。

## 2. 效果的第一性原理修复

### 2.1 渐变把形状“吃掉一半”

`GENERATE` shader 的渐变/杂色分支原本：

```glsl
color = mix(ColorA, ColorB, t);
fragColor = vec4(color.rgb, color.a * texture(Source, vUv).a);
```

`gradient_ramp` 的注册表默认 `end = 0x00000000`（透明）。于是渐变末端 alpha=0，
**形状的右半边直接消失**——用户看到的“渐变不生效/像蒙版”有一半是这个原因。

修复：渐变和分形杂色只替换颜色，**保留图层自身 alpha**：

```glsl
color = vec4(mix(ColorA.rgb, ColorB.rgb, t), 1.0);
fragColor = vec4(color.rgb, color.a * texture(Source, vUv).a);
```

圆形/网格仍然使用自己的 alpha（圆外透明、网格线外透明），不受影响。

### 2.2 旧工程渐变变成“硬切”

`EffectRenderer` 读取 `softness` 的回退值是 `0.05`（不是注册表的 1）。对没有该参数的旧
工程，`smoothstep(0.5-0.025, 0.5+0.025, t)` 等价于在中间硬切两色。回退值改为 `1F`，
和注册表一致（1 = 覆盖整个图层的平滑渐变）。

### 2.3 圆形是椭圆

`distance(uv, Center)` 在 UV 空间测量，非正方形图层会画成椭圆。改为按像素测量并用
短边归一化：

```glsl
float d = length((uv - Center) * LayerSize) / max(min(LayerSize.x, LayerSize.y), 1.0);
```

Java 侧不再乘 `0.7071`，`radius` 直接表示“短边的百分比”。

### 2.4 投影方向上下颠倒

`dropShadow` 的 `PassRenderer.draw(..., offsetX, offsetY, ...)` 最终写进 shader 的
`Offset` 是**纹理空间**（V 向上），而角度 0°=右、90°=下是**屏幕空间**。
旧代码直接传 `+dy`，90° 的投影会跑到图层上方。改为传 `-dy`。

### 2.5 已确认正常、不要重复“修”的部分

- 第四轮已修的 `EffectSpace` V 轴（comp UV ↔ 图层局部）是所有效果的基础。
- `DISTORT` / `PIXEL` 的 `localToCompUv` / `localDeltaToComp` 已在第四轮翻 V。
- Blur / Glow / Stroke / Inner / Key / Wipe 的 pass 组合检查过，未发现新的坐标错误。

## 3. 摄像机

第四轮已经修了“摄像机层被当纯色层画出方块”“旋转符号反了”“solo 误伤”。本轮补充：

1. **拖动摄像机不再旋转画面**：以前 `cameraLookAt` 默认开、目标点锁在合成中心，
   一拖摄像机 `dx/dy` 立刻让 look-at 角度翻转 180°。现在：
   - 新建摄像机默认 `cameraLookAt = false`（纯平移/缩放）；
   - 拖动摄像机时，目标点按相同位移跟随（保留相机→目标偏移），只平移不旋转；
   - 需要“看向目标”时在检查器里手动打开。
2. **缩放统一为单值**：检查器只有“缩放”一行，写入时同时同步 `scaleX/scaleY`；
   `cameraView` 用 `scale.x`。以前有 X/Y 两行但只有 X 生效，Y 改了没反应。
3. **表达式**：`cameraView` 现在也应用 `expressionX/Y/Rotation`，和普通图层一致。
4. **预览里可选中摄像机**：命中测试对 `camera` 用摄像机 gizmo 的 16px 屏幕范围，
   不再只能从轨道列表选。
5. **重置摄像机**按钮：位置/目标回合成中心、缩放 1、旋转 0、关闭 look-at。
6. **已知限制**：摄像机仍不支持父级链；`cameraZ/cameraTargetZ` 未参与（这是 2D 合成器，
   3D 由 BBS 世界/Replay 绑定负责）。

## 10. 下一轮优先项

1. **混合模式的视觉回归**：给同一张图分别用 Normal / Multiply / Screen / Overlay 截四张图，
   确认在透明背景和实色背景上都和 AE 接近。
2. **效果逐个回归**：42 个效果里优先验证 生成类（渐变/棋盘/网格/圆）、变形类（bulge/pinch/twist/wave）、
   投影/描边/发光，确认 V 轴和 alpha 修复在真实素材上成立。
3. **摄像机 3D 化**：如果要做 Z/景深，需要新的 3D 图层与投影，不在当前 2D 管线内；
   建议继续用 BBS Replay 绑定代替。
4. **多形状图层的渐变填充**：`CompShape.fillGradient` 目前多形状共用一次填充，
   单形状正确；多形状需要按 shape 分别生成 paint。
5. **轨道类型图标**：渐变/棋盘/网格/杂色在轨道里仍显示为纯色图标（类型是 solid），
   可按 effect 类型细分图标。
