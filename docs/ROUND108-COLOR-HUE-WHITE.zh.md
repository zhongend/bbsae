# Round 108 — 色相混合把渐变洗成白色

> 版本 `0.99-hotfix73`。未启动客户端截图；headless GL 像素回归 + 全量测试。

## 1. 现象

给一个渐变/彩色图层设置 **色相** 混合模式后，画面直接变成白色（或背景色），
源图层的颜色完全消失。

## 2. 根因

`ShaderSources.COMPOSITE` 的色相混合原来是标准 HSL 公式：

```glsl
if (Blend == 25) return hsv2rgb(vec3(rgb2hsv(s).x, rgb2hsv(b).yz));
```

即：

- 色相取源图层 `s`；
- 饱和度和明度取背景 `b`。

当背景是白色、灰色或任何低饱和颜色时，`rgb2hsv(b).y ≈ 0`，结果饱和度被强制为 0；
无论源颜色是什么，`hsv2rgb(h, 0, v)` 都只返回灰度/白色。用户看到的就是
“色相一开，渐变直接变白”。

## 3. 修复

在 `ShaderSources.COMPOSITE` 中改成：

```glsl
vec3 sh = rgb2hsv(s);
vec3 bh = rgb2hsv(b);
float sat = bh.y <= 0.0001 ? sh.y : bh.y;
return hsv2rgb(vec3(sh.x, sat, bh.z));
```

语义：

- 背景本身有颜色：保持标准“源色相 + 背景饱和度/明度”；
- 背景是白/灰/黑（无彩度）：保留源饱和度，只采用背景明度，使色相仍然可见；
- 源本身是灰色：`sh.y = 0`，结果仍是灰色，不会凭空产生颜色。

这是“背景无法提供色度时，不把源色度也一起丢掉”的最小修正。

## 4. 同时修的颜色链路问题

### 4.1 全透明像素被写入颜色

`COLOR` 程序开头增加：

```glsl
if (c.a <= 0.0001)
{
    fragColor = vec4(0.0);
    return;
}
```

颜色效果不再对无覆盖像素做 HSV/曲线运算。此前透明区域可能留下白色/异常 RGB，
后续 glow/shadow/tint 如果读取 RGB 而不是 alpha，就会把白色拉进可见区域，
形成白边或整片发白。

### 4.2 颜色叠加样式的共享 uniform

`StyleRenderer.tint` 使用共享的 `COLOR` 程序，但只设置了部分 uniform；
紧挨着的 Colorama 效果会留下 `Colorama/ColoramaA/B/C`，颜色叠加随后会用旧色板
重映射图层。现在显式重置这些 uniform，让图层样式不再受前一个颜色效果污染。

  - 修复前失败、修复后通过；
  - 原有正常/蒙版/排除/乘法/线性加深/减淡等像素断言保持通过。
- `EffectPipelineTest`：
  - 色相类效果在彩色源、半透明渐变源、全透明源上的回归；
  - 生成渐变 + 色相后不会变白。

## 6. 边界

- 色相混合在**黑色**背景上仍会变暗/变黑：黑色没有明度可保留，这是混合模式的
  基本面；需要黑色背景上显示颜色时，用正常/颜色混合或提高背景明度。
- 源图层本身是白色/灰色时，色相混合不会仅凭色相值制造彩度；这是 HSL 的
  定义，不应伪造颜色。
